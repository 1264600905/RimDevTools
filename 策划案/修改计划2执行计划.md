# 修改计划 2：执行计划

## 1. 目标与范围

本计划对应 `修改计划2.txt`，包含四项工作：

1. `doctor` 检查 `0Harmony.dll` 版本，并在版本过低时给出警告。
2. 为卡住的测试事务增加安全清理命令；RimWorld 运行时拒绝清理，并尽量恢复原始 Mod 列表。
3. 允许纯 XML 模组将 `csproj_paths` 配置为空数组。
4. 下一次部署或 `test --deploy` 时自动处理上一次失败留下的 `.rimdev-backup-*` 等部署残留。

本次明确不做事务清单 schema 2，不增加 `kind`、`restoreMode`、`applyIntent` 等字段。继续使用现有 schema 1，通过配置中的 `mods_config_path` 识别 `ModsConfig.xml`，以降低迁移和维护复杂度。

## 2. 已确认的现状

### 2.1 Harmony

- `doctor` 当前只检查 Harmony 模组目录和 `0Harmony.dll` 是否存在，不读取程序集版本。
- 构建时实际使用的是 `RimWorldEnvironmentResolution.References.HarmonyDllPath`。
- 仓库中的 `参考文档\\gamedll\\0Harmony.dll` 当前版本为 `2.4.1.0`，只能作为候选要求版本来源，不能依赖某台电脑的绝对路径。
- 现有测试夹具用文本文件模拟 `0Harmony.dll`，新增版本读取后必须补充有效 DLL 测试替身。

### 2.2 事务

- 事务已经保存原始文件、原始哈希、工具写入后的哈希。
- 发现当前文件既不是原始内容也不是工具写入内容时，会返回 `TRANSACTION_CONFLICT`。
- `test run` 和 `deploy` 启动前会自动尝试恢复遗留事务，但没有人工清理命令。
- 当前强制恢复会恢复整个 `ModsConfig.xml`，可能覆盖游戏后来写入的其他配置；清理命令需要只恢复原始 `<activeMods>`。

### 2.3 纯 XML 模组

- `DeployCommand` 已经支持零个 C# 工程：没有工程时跳过构建和构建引用检查。
- 真正的阻断来自 `ProjectTemplatePreflight`，它把空 `csproj_paths` 当作模板配置错误。
- `ProjectConfig.CsprojPaths` 已经默认为空列表，不需要改变配置模型。

### 2.4 部署残留

- `ReplaceDirectory` 使用 `.rimdev-backup-{runId}` 和 `.rimdev-staging-{runId}`。
- 备份删除失败时只输出警告，下一次部署不会扫描旧的随机目录，因此残留会永久存在。
- 不能无条件删除 backup：如果上次崩溃发生在目标目录移走之后，backup 可能是唯一可恢复副本。

## 3. 执行阶段

### 阶段 0：先建立命令和错误码契约

- 新增命令：

  ```powershell
  RimDevTools.exe test cleanup
  RimDevTools.exe test cleanup --dry-run
  ```

- `--dry-run` 只列出待处理事务和部署残留，不修改文件。
- RimWorld 运行时立即拒绝清理，不等待，使用现有 Busy 退出码，并新增稳定错误码 `GAME_RUNNING_CLEANUP_REFUSED`。
- `TRANSACTION_CONFLICT`、`doctor` 的事务检查和清理失败信息中，都提示可复制的 `test cleanup` 命令。
- 清理命令不经过 `ProjectTemplatePreflight`，以保证项目配置有问题时仍可以救援事务。

涉及文件：`CliApplication.cs`、`CliHelp.cs`、`ExitCodes.cs`（如需要）、`TestCommand.cs`。

### 阶段 1：允许纯 XML 模组部署

修改 `ProjectTemplatePreflight.Inspect`：

- `csproj_paths` 为空：合法，不产生模板错误。
- `csproj_paths` 非空且包含模板路径或模板工程：继续报错。
- 其他模板字段（模组名、日志关键词、About.xml、packageId、模板 DLL）保持原有门禁。

更新根目录 `mod_config.jsonc`、`components/ProjectTemplate/mod_config.jsonc`、两个 README 和 CLI deploy 帮助，明确说明：纯 XML 模组可以使用 `"csproj_paths": []`，此时 deploy 跳过 C# 构建但仍同步 `sync_items`。

验证：空工程列表可通过 doctor、dry-run 和正式部署；含 `MyCustomMod` 等模板占位符的非空工程列表仍被拦截。

### 阶段 2：增加 Harmony DLL 版本警告

新增轻量版本读取逻辑，使用 `AssemblyName.GetAssemblyName(path).Version` 读取 `AssemblyVersion`：

1. 从当前环境解析出的 `HarmonyDllPath` 读取已安装版本。
2. 从稳定的项目构建引用或打包基准取得要求版本。
3. 当 `installedVersion < requiredVersion` 时生成 warning。
4. 相等或更高时标记为 available。
5. DLL 缺失、损坏或版本不可解析时输出明确诊断。

不新增通用 DLL 框架，不扫描其他程序集，不让该检查单独阻塞 `doctor.ready`。建议检查 ID 为 `mods.harmony_version`，详情包含已安装版本、要求版本和路径，并提示“请尝试重新订阅 Harmony”。

补充低版本、相等、高版本、损坏 DLL、纯 XML 项目的测试；测试夹具不得再使用不可解析的文本伪 DLL。

### 阶段 3：事务清理与 ModsConfig 原始 Mod 列表恢复

保持现有事务清单 schema 1，不增加清单字段；通过 `mods_config_path` 的完整路径识别 `ModsConfig.xml`。

清理流程：

1. 发现项目并验证 `mods_config_path`。
2. 获取环境互斥锁。
3. 直接检查 RimWorld 进程；运行中返回 `GAME_RUNNING_CLEANUP_REFUSED`。
4. 逐个处理所有遗留事务，不因第一个冲突而提前结束。
5. 对 `ModsConfig.xml` 从事务备份读取原始 `<activeMods>`，只替换当前文件的 `<activeMods>`，保留其他 XML 节点。
6. 对普通设置文件执行现有哈希安全恢复；备份缺失、XML 损坏或无法确认时保留事务并报告。
7. 全部条目成功后才删除事务目录，并输出 JSON 摘要。

保留 `deploy`、`test run` 启动前的自动恢复能力；遇到冲突时增加 `test cleanup` 提示。正常测试结束的强制恢复语义暂不扩大修改范围，避免本阶段引入额外行为变化。

测试：正常恢复、用户修改冲突、游戏改写 ModsConfig、游戏运行拒绝、备份缺失、XML 损坏、多个事务、旧 schema 1 兼容和重复执行幂等性。

### 阶段 4：部署残留自动恢复

新增部署残留处理器，在正式部署中、取得环境锁并确认 RimWorld 已退出后执行；dry-run 只报告，不清理。

只处理 Mods 根目录下严格匹配的直属目录：

- `.rimdev-backup-{32位十六进制 runId}`
- `.rimdev-staging-{32位十六进制 runId}`

处理规则：

1. 当前目标目录存在：删除旧 backup 和 staging。
2. 当前目标不存在且只有一个可确认属于当前模组的 backup：先恢复目标，再记录恢复结果。
3. 目标不存在但存在多个候选 backup：不自动删除，输出人工处理警告。
4. 路径越界、Reparse Point、名称不符合格式：拒绝处理。
5. 当前运行产生的 staging/backup 不得被预清理逻辑误删。

涉及 `DeployCommand.cs`、新增 `DeploymentArtifactRecovery.cs` 和回归测试。验证直接 `deploy` 与 `test run --deploy` 都使用相同清理逻辑。

### 阶段 5：文档、回归和发布检查

更新顶层 CLI 帮助、`README.md`、`RimDevTools/README.md` 和模板配置，记录纯 XML 配置、Harmony warning、事务清理和部署残留恢复规则。

回归顺序：

1. `RimDevTools.Tests`
2. `RimDevTools.ReleaseTests`
3. 纯 XML 模组 dry-run 和正式部署
4. C# 模组 deploy/test 回归
5. 人为制造事务冲突、游戏运行、备份残留三类故障进行验收

## 4. 验收标准

- `doctor` 能准确报告已安装 `0Harmony.dll` 版本，低版本只产生 warning。
- `TRANSACTION_CONFLICT` 后可执行 `test cleanup`，并得到清晰的逐事务结果。
- RimWorld 运行时清理命令不修改任何文件。
- 清理 `ModsConfig.xml` 时恢复原始 `<activeMods>`，不覆盖其他配置节点。
- 事务清单仍为 schema 1，旧事务无需迁移即可处理。
- `csproj_paths: []` 的纯 XML 模组可以部署，且不会触发 C# 构建门禁。
- 下一次 `deploy` 或 `test --deploy` 能安全处理失败遗留的 `.rimdev-backup-*`。
- 所有清理失败都保留可诊断现场，不静默删除数据。
- 清理和恢复流程可重复执行，不产生第二次破坏。
