# LogSyncMod DebugAction 测试工具与物资配置弹窗实施计划

- 日期：2026-10-27（北京时间）。
- 代码基线：`b9adc56`；实施分支：`codex/logsync-debug-tools-1.7`。
- 状态：已实现并部署 LogSyncMod 1.2.2 的工作与暴力解禁；按用户要求不运行测试，由用户进行游戏内验收。
- 官方接口证据：按用户要求，统一使用 RimSage 1.7。

## 1. 本次交付范围

新增一组手动测试用 DebugAction，帮助开发者快速准备物资和测试小人。

| 功能 | 本期行为 |
| --- | --- |
| 测试物资弹窗 | 新建、复制、命名、删除和保存多个物资方案，显示各方案的物品数量与模组分布；选好后点击地图生成 |
| 心情与饱食框选开关 | 同一个框选功能同时锁定满心情、满饱食；再次框选对应小人则移除这组状态 |
| 技能与工作速度框选开关 | 同时锁定全部技能20、赋予固定10倍工作速度、临时解除工作与暴力禁用；再次框选移除整组状态并恢复原有限制 |
| Message 提示 | 每次框选完成后，用游戏内 Message 明确提示添加、移除和跳过的结果 |

以下内容已被物资生成方案替代，不进入本期：零材料蓝图、免费建造、跳过制作原料、修改 RecipeDef/ThingDef 的材料成本。

“全属性 20”在本计划中解释为全部技能 20，不把意识、身体部位效率、移动速度、命中率等其他属性统一设置为 20。需求锁定默认指满心情、满饱食，而非冻结添加时的任意数值。

小人操作只有上述两组独立的框选功能。技能锁定与工作速度必须一起添加、一起移除；不提供单独技能命令、单独倍率命令或专门的移除 DebugAction。按用户最终要求，工作倍率固定为 10 倍，省去倍率选择。

## 2. 物资默认配置

### 2.1 基础规则

从当前游戏已经加载的 ThingDef 中，选择同时满足以下条件的物品，每种默认生成 **1000 个**：

1. `category == ThingCategory.Item`，且通过正常调试生成的可用性检查。
2. 属于原版 `ResourcesRaw` 分类或任意层级的子分类。
3. 当前生效的 `stackLimit >= 75`。

包含已启用模组中正确归入该分类的资源。堆叠上限取当前运行时 Def 的最终值，包含 XML Patch、堆叠模组等修改后的结果；不按地图现有库存、不按某个现有物品堆的数量筛选。

分类枚举可使用 `ThingCategoryDefOf.ResourcesRaw.DescendantThingDefs`，按 `defName` 去重。也可用 `ContainedInThisOrDescendant(def)` 判断归属。不要额外要求 `IsStuff`，否则会遗漏不属于建造材质的原材料。

### 2.2 显式追加默认物品

以下条目不受“原材料分类”和“堆叠上限 >=75”限制：

| 用户名称 | 原版 DefName | 默认生成数量 | 1.7 核实的原版堆叠上限 |
| --- | --- | ---: | ---: |
| 布料 | `Cloth` | 1000 | 75 |
| 零部件 | `ComponentIndustrial` | 300 | 50 |
| 高级零部件 | `ComponentSpacer` | 100 | 50 |
| 奢侈食物 | `MealLavish` | 100 | 10 |

本计划将“奢侈食物”映射为普通豪华餐 `MealLavish`。素食豪华餐 `MealLavish_Veg`、肉食豪华餐 `MealLavish_Meat` 不自动追加，允许用户在列表中自行选择。

基础规则与追加清单取并集。同一个 Def 只保留一行；显式追加数量优先于基础规则数量，绝不因命中两条规则而重复生成。

按原版定义，金和银的上限为 500，新规则会将其纳入；75 上限的钢铁、石块等继续纳入。布料属于纺织品，零部件属于加工品，餐食属于食物，依靠追加清单纳入。

### 2.3 用户修改优先级

最终配置顺序：**基础默认规则 → 显式追加默认物品 → 用户逐项覆盖**。

- 用户可取消默认物品，也可从其他分类、其他堆叠上限的候选物品中勾选新条目。
- 用户覆盖优先级最高。例如取消钢铁后，重新打开窗口不能又被默认规则自动勾回。
- 每行允许修改数量。原材料规则与上述四项仍使用用户明确指定的数量；其他物品初始为 **3 组，即当前 stackLimit ×3**。例如上限75为225个，上限500为1500个，上限1为3个。
- 数量指本次新增量，不是把地图库存补足到目标值。
- 数量为正整数；空值、负数、小数或溢出时显示行内提示，并阻止开始放置。统计总数量使用足够宽的整数类型。
- 原材料与堆叠条件只负责生成默认勾选，不限制用户手动添加的候选物品。

## 3. 独立物资弹窗

### 3.1 入口与布局

开发者菜单 `LogSyncMod` 分类直接平铺显示测试物资、心情与饱食开关、技能20与工作10倍开关。使用原版 DebugActionYielder 注册本地化的三个入口，不增加 Test tools 等二级分组。测试物资打开独立 `Window`，小人测试命令不放进物资窗口。

建议初始尺寸约 **1080 × 720 个游戏 UI 单位**，按 `UI.screenWidth/UI.screenHeight` 限制在可见区域内。窗口有关闭按钮、可拖动，打开时暂停游戏并吸收窗口外输入；关闭后遵守游戏原有暂停状态。

采用原版深色面板、清晰表格和少量蓝绿色强调色，视觉风格与游戏一致。主要按钮突出显示；减少大面积装饰和厚重边框。

┌ 测试物资                                                   × ┐
│ 方案：默认方案 ▾    [方案名称]         [新建] [复制] [删除]     │
│ 此方案 N种 / M个 · 来源：Core K种、模组A L种…（悬停看完整）    │
│ 搜索 名称 / DefName / 模组…              模组：全部 ▾          │
│ [全部物品] [默认物资] [已选物品]             仅第三方模组 □    │
├──────────────┬───────────────────────────────────────────────┤
│ 物品分类     │ □  物品名称          来源模组    最大堆叠 数量 i│
│ 全部         │ ☑ ▣ 钢铁            Core           75  1000 i│
│ 原材料       │ ☑ ▣ 白银            Core          500  1000 i│

该线框表示结构与层次，不是最终像素稿。小屏幕优先保留物品名、模组、最大堆叠、数量和信息卡按钮，压缩侧栏；列标题与行内容不能相互覆盖。

### 3.2 物品行规范

| 区域 | 内容与行为 |
| --- | --- |
| 勾选 | 表示是否加入本次生成；仅点击复选框或指定名称区切换 |
| 图标 | 使用原版 `Widgets.ThingIcon`，约 28–32 单位，不为列表创建物品实体 |
| 物品名称 | 当前语言的 `LabelCap`；长名称截断，悬停显示完整名称与 DefName |
| 来源模组 | `def.modContentPack.Name`，Core/DLC/第三方均显示；悬停补充 PackageId |
| 最大堆叠 | 当前 `def.stackLimit`，右对齐，明确区别于本次生成数量 |
| 数量 | 可编辑整数框，约 80–96 单位；点击输入不改变勾选状态 |
| 信息卡 | 直接使用原版 `Widgets.InfoCardButton`，打开真实 `Dialog_InfoCard` |

行高建议 40–44，使用轻微交替底色、悬停高亮和低饱和度选中背景。不要仅靠颜色表达选中或错误；保留复选框和文字提示。列标题固定，内容区滚动。

来源表示 **Def 所属的内容包**，不声称能追踪最后修改该物品的 Patch 来自哪个模组。未知来源显示可读的“未知来源”，仍可按 DefName 搜索。

点击 `i` 后物资窗口保留选中项、搜索、数量和滚动位置；信息卡关闭后返回原状态。按钮占独立点击区域，不能触发行勾选或地图放置。

### 3.3 筛选与选择语义

- 候选列表来自当前已经加载的全部可生成 `Item` Def，不限于原材料。包括原版、DLC、当前启用的模组；不枚举仅安装但未启用的模组。
- 候选资格参考 `DebugThingPlaceHelper.IsDebugSpawnable(def)`，先检查 `thingClass` 有效，再处理特殊上下文物品；不自行复制一整套原版生成器。
- 使用原版分类树数据构建左侧分类导航。自定义右侧列表负责额外列，避免修改或 Harmony 替换原版 `ThingFilterUI`。
- 分类数据包含已启用模组注册的 ThingCategoryDef 及其子分类；只列出含可生成候选物品的分类。没有父节点的模组自定义分类也作为导航项显示。没有自定义分类的模组物品仍可按来源模组筛选。
- 搜索匹配本地化名称、DefName、来源模组名称和 PackageId；与分类、模组过滤共同生效。
- “默认物资”显示命中当前默认规则或显式追加清单的物品；“已选物品”显示全部当前勾选项。
- 模组下拉支持全部、Core、每个 DLC 和每个第三方内容包；另提供仅第三方模组的快捷过滤。
- 切换筛选只改变可见结果，不取消被隐藏的勾选；底部汇总始终计算全部已选物品。
- “勾选当前结果/取消当前结果”只作用于过滤后的全部结果，不限当前可见屏幕内的行，不影响其他隐藏条目。
- 默认按物品名称稳定排序，同名时按来源和 DefName 排序。排序不能因每次勾选而让行跳动。
- 没有结果时显示空状态及清除筛选入口；没有勾选物品时禁用放置按钮。
- `MadeFromStuff` 物品使用经过校验的原版默认材质；无法解析合法材质时标记不可生成并说明原因。本期不增加单独的材质编辑器。

原版 `ThingFilterUI.DoThingFilterConfigWindow()` 的主要输出为分类树，不能直接满足来源、堆叠上限、数量等固定列的要求。本期复用分类数据、图标与信息卡控件，制作独立表格；不复制食物政策、储存设置中的耐久/品质筛选。

### 3.4 状态与保存

窗口使用独立的多方案草稿，不直接修改地图或立即写入用户设置。

- 方案下拉：各方案显示名称、物品种类、物品总数、来源模组数及模组分布，悬停查看每个模组的完整种类数/物品数。
- 当前方案摘要：始终按方案的全部已选条目统计，不受搜索、分类和模组过滤影响；来源过长时截断显示，悬停看完整分布。
- 方案名称输入框：直接编辑当前名称，保存时要求非空且不与其他方案重名。
- “新建”：新增一个空白方案，未明确规定数量的物品按3组初始化。
- “复制”：将当前方案复制为新的独立清单；随后可以改名、改选择和数量，不影响原方案。
- “删除”：从本窗口草稿中删除当前方案，至少保留一个方案；保存后才持久生效。
- 切换方案：保留当前方案在本窗口内的编辑，不自动写盘；已选物品有无效数量时先要求修正。
- “取消”或关闭窗口：丢弃本次未保存的新增、删除和内容修改，不生成任何物品。
- “保存方案”：保存本窗口内所有方案的编辑、创建、删除与当前方案 ID，窗口保持打开。按钮悬停提示该保存范围。
- “选择地图落点”：校验并保存所有方案，再关闭窗口，只生成当前方案快照。
- “恢复默认”：只把当前方案恢复为原材料规则加四项指定补给，其他方案不变；仍需保存或开始放置才落盘。

在 `LogSyncSettings.debugSupplyProfiles` 中持久化方案 ID、名称、是否采用默认规则和物品条目；条目记录 DefName、是否加入、数量、来源模组名及 PackageId。`debugSupplyActiveProfileId` 记住上次保存时的当前方案。所有保存对象与窗口草稿深复制，避免关闭窗口后留下未保存的内存修改。

默认方案沿用动态默认规则与逐项覆盖；新启用模组的合规资源可以自动进入默认方案。新建与复制的方案采用独立清单，不自动添加之后启用模组中的物品。对某方案执行恢复默认后，该方案重新采用动态默认规则。

旧版单份 `debugSupplyOverrides` 在首次使用时迁入默认方案，保留原来的选择和已保存数量；只有保存新方案结构后才清空旧记录。未加载的物品条目保留其数量和已知来源，方案摘要列明未加载种类数，暂不生成；重新启用对应模组后可恢复。

## 4. 地图放置流程

### 4.1 从窗口到地图

1. 点击“选择地图落点”时生成本次配置的不可变快照，保留原地图引用。
2. 创建原版 `DebugTool`，提示“左键放置测试物资，右键取消”；实际取消按原版工具机制处理，并在实施时验证 Esc。
3. 鼠标点击时再次检查开发者模式、原地图仍有效、当前仍位于该地图、点击格在范围内。
4. 只执行一次本次快照；完成或失败后清除工具。后续再次生成需重新从入口发起，避免误点连续铺满地图。
5. 点击落点之前取消，不产生物品；已经保存的配置仍保留。

### 4.2 生成、分堆与空间

- 每种按当前 `stackLimit` 拆成合法堆，再使用 `ThingMaker.MakeThing` 和 `GenPlace.TryPlaceThing` 放置。
- 75 上限的 1000 个为 13 堆 75 加 1 堆 25；500 上限的 1000 个为 2 堆；零部件 300/50 为 6 堆；高级零部件 100/50 为 2 堆；豪华餐 100/10 为 10 堆。实际拆堆总以当前生效上限为准。
- 以点击格为中心向周围合法格展开，不要求全部重叠在同一个格子；可合并现有同类未满堆，仍按实际新增量计数。
- 优先附近空地。原版 `Near` 有有限搜索范围，不能假设一次调用会无限扩展；材料种类较多时逐步扩大候选落点，搜索限制在当前地图内，并复用扫描结果减少重复遍历。
- 通过合法格检查和放置校验排除边界外、阻挡地形、建筑占据等不可放置区域。不用覆盖/清空现有建筑和物品的方式制造空间。
- 创建和放置都在游戏主线程。根据实际总堆数决定是否使用原版长任务或主线程分批，避免大量模组资源造成明显卡顿；不使用后台线程直接操作 Verse 对象。
- 对数量统计、放置循环设有限边界；不静默抽样、不擅自减少用户选择的材料种类或数量。

### 4.3 部分成功与反馈

`TryPlaceThing` 返回失败时可能已经合并或放置了一部分，不能仅凭布尔结果推断生成数量。通过 `placedAction` 等实际放置结果累计每种新增数量，剩余数量单独处理。

- 空间足够时全部生成；结束提示已放置的种类数和物品总数。
- 空间不足或某一 Def 无法生成时，保留已经成功放置的物品，提示“部分完成”，列出对应物品的请求/实际/未放置数量。
- 重试只处理尚未放置的余量，禁止重新生成完整请求而导致重复物资。
- 清理尚未放置的临时对象，不删除已合并到地图中的现有堆。
- 对单个模组 Def 的生成失败给出清楚记录，可继续处理其余条目；不让一个失败导致所有资源无反馈地中断。
- 简明游戏消息负责结果，`[LogSyncMod]` 日志记录逐项失败与统计；成功过程不逐堆刷日志。

预估堆数为各项 `ceil(数量 / stackLimit)` 之和，不考虑与现有堆合并，UI 标注“约”。

## 5. 小人测试状态

### 5.1 共同规则

- 使用 `DebugToolsGeneral.GenericRectTool()`，原版操作为依次点击两个角点。
- 获取当前地图中位置落在矩形内的活小人，不依赖当前 Selector；先收集快照，再添加/移除 Hediff。
- 默认目标为区域内当前玩家阵营的类人小人；跳过尸体、动物、敌人及不存在相应需求/技能的目标。矩形命令应明确标注该目标范围，反馈成功与跳过数量。
- 使用本工具独立、可见的测试 Hediff，不复用现有炮塔靶子 Hediff，避免附带眩晕、减伤等效果。
- 每次矩形操作内，每个小人只处理一次；按该小人是否已有对应组的状态执行“无则添加、有则移除”，不重复叠加。不能根据框中第一个小人的状态给整组统一赋值。
- 两组开关互不影响：需求框选只切换需求状态；技能与速度框选只切换技能和速度整组状态。移除只处理对应组的本工具 Def，不调用 `RemoveAllHediffs()`。
- 状态随 Hediff 保存。开发者模式只控制命令入口；关闭开发者模式不静默删除已经添加的状态。
- 功能独立于 AutoTestRunner 的运行会话，不需要开启 `autoTestEnabled`，也不自动修改其他测试用例的环境。

### 5.2 心情与饱食

建议 Def：`LogSync_DebugNeedsLock`。

框选到没有该 Hediff 的目标时添加；框选到已有该 Hediff 的目标时移除。一次操作始终同时控制心情与饱食，不拆成两个开关。

添加后立即设置 `mood.CurLevelPercentage = 1f`、`food.CurLevelPercentage = 1f`，不存在的需求跳过。食物上限可因体型、生命阶段和 Stat 改变，不能写死 `CurLevel = 1f`。

采用带 Hediff 条件的需求冻结或定点需求访问处理，使正常游戏更新下读数稳定为满；Comp 负责初次设置、读档/上限变化后的校正。Harmony 只作用于 Food/Mood 且必须存在本工具标记，其余需求走原版。

不能只定时补满却宣称严格锁定，也不能只用 `hungerRateFactor = 0`。不要整体跳过 `Need_Mood.NeedInterval()`，以免连同思绪和观察器更新一起停用。

保留已有精神状态、营养不良、其他疾病和伤口。冻结食物需求可能同时停止原版营养不良的自然变化，实施说明与验收应明确这一点；本期不把锁需求变成治疗命令。第三方直接修改内部需求字段的行为不作通用保证，按实际冲突定点适配。

### 5.3 技能 20 与工作速度：同一组框选功能

使用 Def：`LogSync_DebugSkilledWorker10x`。同一个 Hediff 同时代表技能 20 和工作 10 倍；不另设独立技能或速度 Hediff。

直接进入框选工具。对每个小人，已有本组 Hediff 就移除，没有就添加。添加时技能与速度一同生效，移除时一同恢复。

#### 5.3.1 技能部分

- 技能补丁识别上述任意一个本组 Hediff。临时覆盖带标记小人的 `SkillRecord.GetLevel()`、`GetLevelForUI()` 等必要读取路径，必要时覆盖 `GetUnclampedLevel()`，使技能计算与展示一致，并处理基因资质后的最终结果。
- 对带标记技能暂停原版 `Learn()` 写入，包括学习和遗忘，避免解除后真实技能已经被测试过程改变。
- 不周期性把 `levelInt` 写成 20，不永久改写原有等级、经验、热情、背景或基因。
- 移除后恢复原版读取和学习/遗忘；普通情况下回到添加前的底层等级、经验。第三方直接改写记录不在本工具的恢复承诺内。
- 按用户后续要求，带本组 Hediff 时临时覆盖 `Pawn.CombinedDisabledWorkTags` 为 None、`Pawn.GetDisabledWorkTypes()` 为独立空列表，同时使 `SkillRecord.TotallyDisabled`、`PermanentlyDisabled` 返回 false。角色卡不再因为工作禁用而把医术、社交等显示为“—”，原版无暴力判定也随之解除。
- 整组添加/移除后调用 `Notify_DisabledWorkTypesChanged()`，并刷新工作分配的 WorkGiver 缓存，保证技能禁用缓存与界面状态及时更新。
- 不删除背景、特性或基因，不清空原始缓存列表，不强制修改玩家设置的工作优先级；原有身体健康要求仍适用。移除本组 Hediff 后恢复原始工作与暴力禁用判定。

#### 5.3.2 工作速度部分

通过同一个技能与速度 Hediff 阶段的 `statFactors.WorkSpeedGlobal` 设置固定 10 倍倍率。

- 本组只有一个 Hediff；重复框选移除整组状态，不叠加倍率。
- 倍率作用于小人当前全局工作速度，实际速度同时包含 20 技能对应的正常加成。
- 不同时把 ConstructionSpeed 等派生速度再乘同一倍率，避免二次相乘。
- 框选直接调用整组开关逻辑，不增加独立的技能、速度设置、倍率选择或恢复命令。
- 整组添加和移除后验证相关 Stat 缓存及时更新，必要时仅清除相关小人的相关 Stat 缓存。
- 原版 ConstructionSpeed 明确依赖 WorkSpeedGlobal；制作效果取决于配方的 workSpeedStat。固定等待、移动速度、自定义 JobDriver 和不使用此 Stat 的流程不承诺等比例加速。
- 不用全局 `DebugSettings.fastCrafting` 代替本功能，避免影响其他小人和固定的原版倍率。

### 5.4 重复框选与 Message 提示

按每个小人的本组状态独立翻转，以矩形操作开始时收集的目标快照为准：

| 操作 | 小人已有状态 | 本次结果 |
| --- | --- | --- |
| 心情与饱食框选 | 无需求锁 | 同时添加心情与饱食锁 |
| 心情与饱食框选 | 已有需求锁 | 同时移除心情与饱食锁，不影响技能与速度 |
| 技能与速度框选 | 无技能与速度状态 | 同时添加技能 20 与工作 10 倍 |
| 技能与速度框选 | 已有本组状态 | 同时移除技能锁和工作倍率，不影响需求锁 |

混合框选时，已有状态的小人移除，没有状态的小人添加；例如 3 人中 1 人已有需求锁，完成后应为“添加 2、移除 1”，不是整框统一添加或统一移除。

每个矩形完成后调用游戏原版 `Messages.Message(...)` 提示结果，不以日志、Letter 或额外确认弹窗代替。默认使用 `MessageTypeDefOf.NeutralEvent`、`historical: false`，不进入历史档案。单目标可带姓名，多目标合并为一条统计，避免逐人刷屏。

示例文案：

- `心情与饱食：已添加 2 人，已移除 1 人，跳过 0 人。`
- `技能 20 + 工作 10 倍：已添加 3 人，已移除 2 人，跳过 1 人。`
- `已移除张三的技能锁与工作倍率。`
- `未找到符合条件的小人。`

统计以实际操作结果为准，发生异常时标明失败数量，不能把失败计为添加/移除成功。工具提示也应说明“再次框选可移除对应状态”。

## 9. 验收用例

### 9.1 配置规则

1. 以原版未被改动的 Def 验证：钢铁、75 上限石块、500 上限金银均默认选中，各 1000。
2. 原材料分类中低于 75 的物品不自动加入；不在该分类的其他物品不因堆叠大就自动加入。
3. 四个追加项数量分别为 1000/300/100/100，不受阈值限制；规则与追加命中同一 Def 时只有一项。
4. 新启用模组的合规资源进入默认集合；不合规的普通模组 Item 仍可手动选择。
5. 修改堆叠上限后默认集合按最终值更新；用户已保存的取消/追加/数量覆盖仍然优先。
6. 取消钢铁、手动添加其他物品并修改数量，保存、重开、重启后仍正确；移除再恢复模组不会丢掉其覆盖记录。
7. 新增未明确规定数量的物品，上限75/500/1分别初始化为225/1500/3；明确指定的物资仍按原数量。
8. 新建、复制、命名、切换并保存多个方案，重开后方案、名称、选择与数量互不混淆；关闭窗口不保存时不改变已有配置。
9. 每个方案的总种类/总数量和按模组分布与全部条目一致；搜索筛选不改变方案总计，未加载条目可辨认并保留。

本次按用户要求不编写或执行测试，以下清单保留给用户手动验收。编译和部署检查不等于游戏运行验证。

### 9.2 UI 与操作

1. 1920×1080、较小分辨率和游戏 UI 缩放下，窗口在屏幕内，列和底栏无重叠，长中文/英文名称不会挤掉 i 按钮。
2. 名称、DefName、模组名称、PackageId 搜索生效；来源与最大堆叠展示正确。
3. 切换分类和模组不会丢失隐藏勾选；批量勾选只影响当前过滤结果；汇总与全部已选一致。
4. 点击数量框和 i 不切换勾选。关闭 InfoCard 后仍保留草稿和滚动位置。
5. 无结果、无勾选、无效数量、未知来源都有清楚的界面状态；输入无效时不会生成物资。
6. 截图检查空列表、长名称、多模组、大量条目、已选页和 InfoCard 叠层，实际检查文字对比、边距和按钮层次。

### 9.3 放置

1. 在足够空地放置默认配置，逐 Def 统计地图新增量，与请求完全一致；现有库存不被误算为新增。
2. 每个新堆不超过当前上限；允许与现有堆合并，统计仍准确。
3. 在地图边缘、狭小房间、已有堆旁、阻挡区域及大量模组资源下测试，无越界、无覆盖删除、无死循环。
4. 空间不足及单个 Def 异常时提示部分成功和余量，不重复生成已成功数量，不遗留未放置的临时对象。
5. 工具取消、切图、退回主菜单、连续鼠标输入不会触发重复或跨地图放置。

### 9.4 小人状态

1. 区域内符合目标范围的小人切换对应组状态，区域外、敌人、动物不受影响；同一小人在一次框选内只处理一次，再次框选会移除，再框选会重新添加。
2. 心情和饱食在持续游戏更新后稳定为满；改变食物上限、保存读档后仍正确；其他需求正常更新。
3. 带负向技能资质的小人可验证最终技能读取为 20；正常学习与遗忘不改变其底层记录，移除后恢复正常读取。
4. 技能20与10倍速度同时生效；再次框选同时移除二者，无残留；无标记小人不受补丁影响。
5. 比较相同健康、技能、环境下的工作 Stat 和实际工作进度；区分技能变化与倍率变化，确认派生速度没有被重复相乘。
6. 两组框选互不影响。技能与速度组同时解除工作与暴力禁用，移除时恢复原始禁用；背景、特性、基因和其他健康状态保留。菜单没有单独的解禁或专门移除命令。
7. 验证原版建造及使用相关速度 Stat 的普通制作；对固定等待/自定义流程记录覆盖边界，不笼统宣称所有动作都加速。
8. 同一个矩形内混合已有/未有状态的小人，按各人状态翻转，Message 的添加/移除/跳过数量与实际一致；单目标提示可辨认姓名。
9. 连续重复框选、空框选和含不合格目标的框选均有正确的 Message，不只输出日志，不弹 Letter 或确认窗口。
10. 选有医疗、社交、灭火或无暴力禁用的小人，添加后角色卡可显示对应20技能，工作页可正常分配相关工作，原版装备武器/攻击入口不再因无暴力拒绝；移除后恢复原有限制。此项由用户游戏内验收。
