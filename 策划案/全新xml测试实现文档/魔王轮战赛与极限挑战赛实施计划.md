# 魔王轮战赛与极限挑战赛实施计划

制定日期：2026-11-09。

状态：首版已实现，极限挑战优先人数增长，同时支持 CP 配兵预算增长。代码、配置、逐档名册、独立校验和赛后列表已接入，巡礼按身份拆页，默认测试场地隔离后置生成内容；验收结果以实际工具输出与聊天记录为准。本文保留实施设计，不替代测试报告。

## 1. 目标、复用范围与难度

在现有擂台体系内增加两个与单败淘汰赛并列的赛制：魔王轮战赛、极限挑战赛。参赛单位继续使用现有组合，可为单一 PawnKind、异种配置或 SquadTemplate 混编。

大部分已有能力可以复用。主要工作集中在赛事调度、极限挑战的逐档配兵、成绩汇总和工具校验。无需重新实现单场战斗、原生 AI、伤害采集、镜头或整个展示流程。

| 工作项 | 方案 | 难度 |
| --- | --- | --- |
| 战斗地图、双方生成、开战、原生 AI、复活与召唤、战后清理 | 复用 CombatFightService 及现有底层 | 低，主要做接入回归 |
| 参赛者巡礼、赛前展示、镜头、左右统计、单场结算 | 复用，补充身份、进度和增长数值 | 低到中 |
| 魔王轮战赛 | 新增固定交叉配对调度和魔王成绩汇总 | 中等偏低 |
| 极限挑战赛：人数或配兵预算增长 | 在交叉配对之上新增逐档挑战、名册和上限处理 | 中等 |
| 极限挑战赛：角色属性增长 | 新增属性倍率机制，涉及生命、伤害、冷却等不同实现 | 较高，独立评估 |
| 赛后天梯页面 | 复用页面外框、卡片、动画和导航；按赛制提供内容 | 中等偏低 |
| 配置、结果、超时、独立校验和验收 | 扩展现有 arena 链路 | 中等，属于必要工作 |

天梯页面以实现成本和表达准确性为准。现有淘汰树无法直接表达重复挑战，允许新模式使用简单的赛程列表和成绩表，不要求保留树形结构，也不把复杂矩阵、全新动画列为首版必需项。

默认空白场地还需隔离原生世界地块变体和生态区附加生成步骤，避免铺平后被后续步骤生成废墟。隔离仅限工具自建的默认空白地图，不修改源世界地块；生成完成、放置参战者之前检查残留物与地形，异常直接终止。巡礼按魔王、挑战者分别分页，单场对阵预览仍展示双方。

不作精确复用比例或工期承诺。魔王轮战赛的规则较简单；极限挑战赛的主要变量是“增长什么”，而非战斗界面。两者整体属于现有功能扩展，属性强化另算。

## 2. 已确认需求与建议默认规则

已确认：

- 两种新赛制与原擂台淘汰赛并列。
- 魔王轮战赛支持一个或多个魔王组合和一个或多个对手组合；每个对手依次挑战每个魔王。
- 最终界面显示每个魔王组合的胜利场次与平均分数。
- 极限挑战赛中，挑战者每次战败后，按配置乘以倍率或增加固定人数 / CP 预算；在上限内持续挑战，直到获胜。
- 尽量复用已有 UI；天梯页面不适合复用时可以替换。
- 极限挑战优先人数增长，同时支持 CP 配兵预算增长。
- 魔王和挑战者巡礼分别展示；手动配置的混合巡礼页自动按身份拆页。
- 三种赛制准备参赛者时显示观众规则页，现实时间至少 5 秒；加载超过 5 秒则完成后直接进入巡礼。
- 新赛制结算使用双方肖像、胜者高亮、评分、下一场安排和带图标的交锋记录，最终成绩使用肖像卡片。

以下是为形成可实施方案提出的默认规则，尚未得到用户逐项确认。实现时应在配置、界面和使用说明中保持一致，不将其表述为已确认需求：

| 规则 | 建议默认 |
| --- | --- |
| 每场双方状态 | 重新生成完整阵容，不继承伤势、消耗和死亡 |
| 多魔王的增长进度 | 每个“挑战者 × 魔王”独立，从初始数值开始 |
| 魔王轮战平均分 | 平均胜利评分，即魔王胜局评分之和 / 胜场；零胜场显示“—” |
| 极限挑战增长对象 | 首版支持人数、combatPower 配兵预算；角色属性强化单独设计 |
| 平局 | 当前档位按现有次数重赛，耗尽后该组记为未决并继续其他组 |
| 极限挑战达到上限 | 等于上限允许挑战；下一档超过上限则本组结束，不反复停在上限重打 |
| 顺序 | 对手按配置顺序作为外层，魔王按配置顺序作为内层 |
| 左右位置 | 新模式默认魔王在左、挑战者在右，并明确角色标签；换边对照不纳入首版 |

若“平均分”需要覆盖败局，可另选“胜局沿用原分、败局为 0”的场均得分；它与平均胜利评分含义不同，不能在实现中混用。本文后续以平均胜利评分为推荐口径。

## 4. 配置与兼容策略

继续使用 `test run --mode arena --scenario-path ... --test-name ...`，在赛事配置中区分赛制。产品上是并列赛制，技术上共享现有 arena 会话、启动、音频、暂停、截图、取消和配置事务链路。

建议增加：

- Tournament.format：`knockout`、`bossRoundRobin`、`limitChallenge`；缺省为 `knockout`。
- Entrant.role：新模式必须为 `boss` 或 `challenger`；轮战中的“对手”也用 challenger 表示。
- Growth：极限挑战专用，包含 `target=count|budget`、`mode=multiply|add`、`maxValue`；乘法用 `multiplier`，加法用 `increment`，两者互斥；省略 mode 兼容原乘法。
- Entrant 自身的 count / budget 继续沿用现有覆盖方式，作为该组合初始值。

以下仅表示拟增加字段，不是当前可运行的完整 XML：

```xml
<Tournament id="boss-demo" name="魔王轮战" format="bossRoundRobin">
  <!-- 原有 testDefName、Scene、Roster、Battle 等配置沿用 -->
  <Entrants>
    <Entrant id="boss-a" squad="bossSquad" role="boss"/>
    <Entrant id="challenger-a" pawnKind="Wolf_Timber" role="challenger"/>
  </Entrants>
</Tournament>

<Tournament id="limit-demo" name="极限挑战" format="limitChallenge">
  <!-- 原有配置和双方名单沿用 -->
  <Growth target="count" multiplier="1.5" maxValue="200"/>
</Tournament>
```

新模式要求魔王、挑战者均至少一个，身份互斥，组合 ID 唯一；同一 PawnKind 可以有不同 ID、数量或异种的组合。仅在新模式放开 PawnKind 去重，避免无意改变原淘汰赛行为。

严格校验未知字段、角色、倍率、上限、增长对象与 Roster 模式的匹配。数量增长要求初始数量配置，预算增长要求初始预算配置；首版不混合两种增长单位。最大值不得小于任一挑战者初始值。

新增语法要求 CLI 与游戏侧使用配套版本；旧 XML 缺省行为和现有淘汰赛种子算法保持兼容。原有 Matchmaking 若在新赛制中显式出现，应拒绝或明确限定为不支持，不静默忽略。

## 5. 魔王轮战赛

### 5.1 调度

对手为外层、魔王为内层；B 个魔王和 C 个对手产生 B×C 个挑战组，每组一场正式对决，可附带平局重赛。

例如两个魔王、三个对手，顺序为：甲对 A、甲对 B、乙对 A、乙对 B、丙对 A、丙对 B。魔王败北也不退出后续赛程；魔王之间、对手之间不交战。

调度是纯逻辑，不依赖 Pawn 或 GUI。原 ArenaScheduler 保留淘汰逻辑；新建轮战调度，输出双方组合 ID、组 ID、顺序和结束状态。无需将所有赛制改造成通用赛事框架。

### 5.2 评分与汇总

原胜负判定和百分制胜利质量公式继续使用。魔王胜利时纳入其评分，挑战者胜利时计魔王一败，挑战者的胜利评分保留在对局明细中。

- 胜场、败场各按正式对决计一次，平局重赛不重复累计。
- 重赛耗尽记该组未决，单列未决数量，不算胜败，不纳入平均胜利评分。
- 平均分使用未舍入评分计算，界面显示两位小数；零胜场为 null / “—”。
- 最终必须显示所有魔王，不能沿用 Take(5) 截断。
- 默认按配置顺序显示魔王；若提供排行，按胜场、平均胜利评分降序，同分按组合 ID 固定排序。零胜场的空平均分不参与数值比较。
- 执行错误、清理失败和现实超时不能转换为比赛失败或未决平局，沿用错误退出并保留已有结果。

例：魔王 A 三组结果为胜 80、败、胜 90，则胜场 2、败场 1、平均胜利评分 85.00；不是将败局计 0 后的 56.67。

## 6. 极限挑战赛

### 6.1 挑战组与增长档位

每个“挑战者 × 魔王”为独立挑战组。挑战者从初始值开始；战败后提升数值再挑战同一魔王，胜利后转入下一组。换魔王或挑战者时增长进度重置。魔王阵容和基准模板在赛事开始时冻结。

每个档位作为一场 ArenaMatch，现有 Attempts 仅用于该档位的平局重赛，不用同一个 Attempts 混合“平局重赛”和“失败后升级”。一个挑战组通过档位对局 ID 列表串联历史。

建议组终态：`won`（攻克）、`limitReached`（下一档超上限）、`unresolvedDraw`（平局重赛耗尽）。这些都是赛程正常走完可产生的比赛结果；整个赛事可以 completed，但汇总必须显示各终态数量。错误、取消和工具超时仍是运行异常状态。

### 6.2 数量增长

采用每次失败后：`nextCount = ceil(currentCount × multiplier)`。倍率必须为可表示的有限数且大于 1，人数和上限为正整数。例如初始 10、倍率 1.5：10 → 15 → 23 → 35。

加法模式为 `nextCount = currentCount + increment`，增量须为正整数，如 2 → 4 → 6 → 8；CP 加法允许正小数，如 100 → 250 → 400。两种模式沿用相同的上限、逐魔王重置、获胜停止和平局规则。

用 decimal 和 checked 算术计算并复核结果。正整数人数配合向上取整保证每次有效失败后人数严格增加。下一档大于用户上限或现有人数上限时结束本组，等于上限允许进行该档。

人数增长使用冻结的基准名单，按基准成员顺序循环复制到目标人数，每个成员的副本数量最多相差一份，保留兵种、异种和配装。固定混编不能只改外层 count；保存本档派生模板和实际成员名单，原模板与历史名册保持不变。

加权 / 派系混编的人数增长同样复制冻结的基准名单；预算增长才按各档预算重新生成阵容。外部 generator 返回不合法名单时报配置 / 执行错误，不暗中替换为其他生成方式。

### 6.3 预算增长

每次失败后：`nextBudget = currentBudget × multiplier`。预算增加后沿用现有 CP 配兵；结果记录请求预算、实际投入、剩余预算和实际名册。

预算增长不保证人数每档增加，混编兵种也可能变化；因此结果不能把“预算乘了多少”直接描述成“实际实力乘了多少”。若相邻档生成相同规模，仍属于不同预算档，按各自配置记录。

固定混编的预算增长不会自动改变成员。首版预算增长明确拒绝固定数量模板，并给出改用数量增长或加权模板的提示；若后续要求预算驱动固定组合扩编，再增加独立分配规则。

沿用当前配兵保护，包括每队最多 200 人、混编预算现有校验范围和阵型边界。数值达到可预见的人数 / 算术限制时记录明确的 limitReason。生成器故障、非法 Def、清理失败不能伪装成正常达到上限。

### 6.4 属性增长的边界

当前没有通用的角色属性倍率能力。修改 combatPower 数值只改变配兵成本，不会自动提高生命或伤害。

如果用户所说“数值”指同人数下的血量、伤害、攻速等，应先明确属性列表、倍率应用位置、护甲和冷却的上限、召唤物 / 复活是否继承及模组支持范围，再独立估算。本文不将其视为人数 / 预算增长的同义替代，也不把首版建议视为用户已选择增长对象。

### 6.5 终止、平局与随机性

- 不新增固定“战败三次就结束”等次数限制；只要下一档有效且不超上限，就继续。
- 平局在原档位重赛；达到重赛上限后该组未决，不默认增加倍率。
- 每组保存初始值、倍率、最大值、当前档、实际名册、历次胜负、首次获胜值和结束原因。
- UI 显示“逐档首次获胜人数 / 预算”，不声称找到了理论最低门槛，也不隐含战斗胜率随人数单调增加。
- 新模式的种子包含赛事种子、双方组合 ID、档位、重赛索引和用途标识；相同输入可复现，不复用旧模式的对局种子到不同档位。
- 魔王使用固定名册 / 生成模板，每场生成新的 Pawn；挑战者每档生成并冻结本档名册，平局重赛复用该档配置。实际初始化和战斗仍按原生机制运行。

## 7. 页面方案：复用外框，按赛制显示内容

### 7.1 当前天梯不能原样沿用的原因

ArenaBracketLayout 会在一方失败后移除其后续树端点，ArenaPostBattleView 会将曾经失败的组合整体标暗，文案也绑定晋级、淘汰和冠军。新模式同一组合会反复参赛，极限挑战还会改变人数，直接套用会导致布局缺失或历史显示错误。

因此保留原淘汰树路径；新模式只复用通用页面能力，不构造假的淘汰关系。

### 7.2 首版最低成本布局

| 区域 | 魔王轮战赛 | 极限挑战赛 |
| --- | --- | --- |
| 页面外框、字体、按钮、暂停展示和截图时机 | 沿用 | 沿用 |
| 顶部双方卡片和结果揭晓动画 | 魔王 / 对手、本场胜败和评分 | 魔王 / 挑战者、本档数值和结果 |
| 主内容区 | 按时间顺序的对战记录与魔王成绩 | 当前挑战组的档位记录与其他组状态 |
| 当前定位、滚动与总览 | 复用交互，定位当前记录 | 复用交互，定位当前档位 |
| 底部提示 | 下一组对阵 / 比赛结束 | 下一档数值 / 本组攻克 / 达到上限 / 未决 |

若沿用树节点绘制和动画所需适配超过简单列表成本，直接为新模式实现列表内容。矩阵作为可选增强；不为复用天梯强行增加树布局适配层。

对象身份色按组合 ID 区分，避免同 PawnKind 不同组合颜色与身份混淆。历史卡片读取该场名册快照，不能读取已经增长后的当前 roster。不得因某组曾经失败，把它在所有后续场次中标为淘汰。

### 7.3 最终成绩

轮战最终页至少显示：魔王名称、胜场、败场、未决、平均胜利评分。所有魔王都可见；多页时自动轮播并允许手动翻页，避免自动结束前只看到了前五。

极限挑战最终页按挑战者与魔王显示：终态、实际战斗次数、有效增长档数、首次获胜人数 / 预算、对应实际人数 / CP、最终倍率或数值比例、终止原因。倍率取实际值 / 初始值，并注明人数存在向上取整。

复用原最终展示的暂停、首个实际绘制帧开始计时、截图和资源释放机制。单页建议沿用 10 秒；多页按页计时并纳入超时估算。原淘汰赛的前五荣誉榜继续使用原逻辑。

## 8. 最小架构与数据改动

1. 给赛事输入增加 Format、角色和 Growth；保留原淘汰输入默认值。
2. 保留 ArenaScheduler；增加轮战、极限挑战的纯逻辑调度器，提取最小共同调用边界：取下一场、接收结算、查询完成状态。绘制和 Pawn 生成不进入调度器。
3. 新增 ChallengePairResult，保存双方 ID、档位对局、终态、首次胜利与上限原因；ArenaMatch 增加组 ID、档位和本档名册信息。
4. 基准 Rosters 与每场 ResolvedRosters 分开保存。极限挑战不修改此前对局引用的对象；魔王的固定名单和挑战者的本档名单均可复核。
5. 新模式使用独立汇总结果；不要给 Champion 填入虚构冠军来绕过完成条件，也不要用 LastVictoryScore 代替平均分。
6. ArenaService 根据赛制选择调度器、赛后内容和最终成绩阶段；共享战斗调用、取消、异常、清理、写结果及正常退出机制。
7. 状态接口增加 format、双方角色、pairId、档位、当前值和已完成组数；复用 arena-status / arena-cancel。

新模式的“completed”指计划内所有挑战组都有合法终态、展示和产物已完成。中途错误保留已完成组，但不能宣称所有魔王都接受了全部挑战。

## 9. 独立校验、总超时与产物

### 9.1 CLI 校验

根据冻结输入分支校验。原淘汰赛继续验证 N−1、配对、晋级、唯一冠军和原排名；新模式不能走该完成判定。

轮战需独立重建 B×C 个组合，验证顺序、无重复无遗漏、角色、每组重赛和终态，并从明细重算胜败、未决、分数总和、样本数和平均值。

极限挑战需独立验证每组初始值、逐档乘法与取整、不得胜后继续升级、不得平局升级、不得超上限开战、不得跨魔王沿用增长、本档名册与原始统计一致。正常达到上限、未决和运行错误分开校验。

两种模式继续复用原始战斗账本、评分、伤害采集降级、模拟 tick、截图、展示时长和清理完整性检查。不能只校验结果文件自行声明的总数或均分。

### 9.2 总超时

轮战预算按 `B×C×(1+MaxReplays)` 次战斗的上界，加巡礼、赛前、赛后和最终展示时间估算。极限挑战按每组合法档位数再乘同档重赛上界。

数量增长按与运行相同的整数递推计算档数。预算增长用同样的 decimal 递推；倍率精度导致增长停滞时拒绝配置。对过多档位和期限溢出明确报告，不能退回 N−1 估算或溢出后继续运行。

总截止时间、心跳和单场现实超时继续保留。它们属于运行控制，不能计为魔王获胜或挑战者战败；不强杀游戏的现有策略继续沿用。

### 9.3 产物约定

继续使用 RimDevTools 自动分配的原始结果、报告和截图路径；新增赛制明细写入现有结果链路，由工具生成。路径以 stdout JSON 的 result.artifacts 或 error.details.artifacts 为准。

不新增测试证据目录、任务目录、日期目录，不另存 stdout / stderr，不复制原始日志、截图或存档；不存在的原始路径如实报告。实施验收结论在聊天中报告，不额外生成测试报告或完成清单。

## 10. 分阶段实施与验收

### 阶段一：契约、配置与纯逻辑

### 阶段二：魔王轮战全链路
