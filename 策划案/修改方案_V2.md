# RimDevTools 修改方案 V2

## 1. 文档状态

本文是 `策划案/修改要求.txt` 的可执行实施规格，基于 2026-08-07 的当前代码、真实测试报告和已确认答复整理。

本轮确认的产品决策如下：

1. 初始化入口使用 `RimDevTools.exe init <version> --output <目录>`，暂不增加模组名、packageId 等参数。
2. 隔离桌面默认开启，适用于 quick、auto、xml 和 `data refresh`。
3. manual 模式默认不进入隔离桌面；只有显式传入命令行开启参数时才进入。
4. `mod_config.jsonc` 保存隔离桌面默认值，命令行参数可以覆盖单次运行，不回写配置。
5. 测试静音采用进程内 Unity 音量临时置零，不修改 Windows 系统音量，也不持久修改玩家音量配置。
6. 与旧 `.tools/test/run_test.py` 的一致性只检查“指定目标模组”和“自动截图”两项，不迁移其余参数。
7. 允许修改并验证独立的 `RimSearcher` 嵌套仓库；必须保留其中已有的用户修改。
8. `--help` 改造成完整 CLI 帮助系统，覆盖顶层、命令组和具体子命令。

## 2. 总体目标

本轮开发完成后，RimDevTools 应满足以下结果：

- `ref pull` 使用安全化后的模组名称作为参考文档目录。
- quick 和 data refresh 分别完成独立真实测试，不再受错误的外层串行超时结论影响。
- 日志量超过阈值时仍能可靠识别 quick、auto/xml 和 data 完成信号。
- 自动测试和数据库刷新默认在 Windows 隔离桌面运行，减少对当前桌面的打扰。
- quick、auto、xml 测试运行期间静音，完成后恢复进程内原音量。
- CLI 可以初始化 1.6、1.7、1.8 三种标准项目骨架。
- 使用正确的失能机关本家 `aoba.deadmanswitch.core` 重跑目标模组自动测试和截图。
- `--help` 能准确说明所有命令、选项、默认值、覆盖关系和示例。

## 4. 配置与命令行契约

### 4.1 新配置项

在 `mod_config.jsonc` 根节点新增：

```jsonc
// 自动启动 RimWorld 的命令是否默认使用 Windows 隔离桌面。
// 适用于 test quick/auto/xml 和 data refresh；manual 默认忽略此值。
"isolated_desktop": true,
```

对应 C# 配置属性：

```csharp
[JsonPropertyName("isolated_desktop")]
public bool IsolatedDesktop { get; set; } = true;
```

旧项目缺少该字段时按 `true` 处理。初始化命令生成的新配置也必须显式写入 `true`。

### 4.2 单次覆盖参数

以下命令新增两个互斥参数：

```text
--isolated-desktop       本次运行强制使用隔离桌面
--no-isolated-desktop    本次运行强制使用当前普通桌面
```

适用命令：

```powershell
RimDevTools.exe test run ...
RimDevTools.exe data refresh ...
```

同时传入两个参数时，在启动游戏和修改配置前返回：

```text
exitCode: 2
error.code: ISOLATED_DESKTOP_OPTIONS_CONFLICT
```

### 4.3 生效优先级

quick、auto、xml 和 data refresh：

```text
显式命令行参数 > mod_config.jsonc isolated_desktop > 内建默认值 true
```

manual：

```text
显式 --isolated-desktop > 内建默认值 false
```

manual 不因配置中的 `isolated_desktop=true` 自动进入隔离桌面。显式 `--no-isolated-desktop` 仍合法，并保持普通桌面。

最终 JSON 结果应包含：

```json
{
  "isolatedDesktop": true,
  "isolatedDesktopSource": "command_line|project_config|mode_default"
}
```

## 5. 改动一：ref pull 使用 name 作为目录

### 5.1 当前问题

当前 `RefCommand.CreateTarget` 使用 `SafeFolderName(mod.PackageId)`，例如：

```text
参考文档/KindSeal.LOL
```

新要求是使用 About.xml 中的 `<name>`，例如：

```text
参考文档/联合重工-UF_Heavy_Industries
```

### 5.2 新命名规则

目标目录名必须由 `ModCandidate.Name` 生成，规则固定为：

1. 对名称执行 Trim。
2. Windows 不允许用于文件名的字符替换为 `_`。
3. 空格和其他空白字符替换为 `_`。
4. 控制字符替换为 `_`。
5. 末尾的空格和点号不得保留；经过前述替换后仍需再次校验。
6. Windows 设备保留名，如 `CON`、`AUX`、`COM1`，在前面加 `_`。
7. 结果为空、`.` 或 `..` 时返回 `MOD_NAME_INVALID`，不得回退到 packageId。
8. 不自动合并连续 `_`，保证每个被替换字符均有可见对应位置。

JSON 结果仍同时保留 `name`、`packageId`、`sourceDirectory` 和 `targetDirectory`。

### 5.3 名称碰撞

不同 packageId 可能拥有相同 name，安全化后也可能产生相同目录名。所有目标必须在复制前统一计算并检查。

发生碰撞时：

- 返回 `TARGET_COLLISION`。
- 输出冲突目录、原始 name 和全部 packageId。
- 不自动追加 packageId 或数字后缀。
- 不创建暂存目录，不修改任何已有目标。

### 5.4 测试

至少覆盖：

- 普通英文名。
- 中文名称。
- 空格替换。
- `:`、`/`、`\\`、`?`、`*` 等非法字符替换。
- Windows 保留名。
- 全非法字符或空名称失败。
- 两个名称安全化后发生碰撞。
- `--deps` 中依赖模组也使用 name。
- `--force` 只覆盖 name 对应的目标目录。

## 6. 改动二：重新检查 quick 和 data refresh

### 6.1 已知证据

现有报告中的未通过不能直接判定为产品缺陷：

- `data refresh --timeout-seconds 180` 被外层宿主的 120 秒总超时强制终止。
- Player.log 显示导出已经处理到 16500/16884 个 Def，但没有机会输出最终完成日志。
- 失败运行留下约 232 MB 的 `defs.db.tmp`，说明终止发生在导出后段。
- 同目录已有此前成功生成并通过完整性检查的 343,728,128 字节数据库。
- quick 的 `RUNTIME_READY_TO_CLOSE` 已出现在 Player.log；只是串行宿主丢失了 CLI 标准输出。

### 6.2 复测方式

必须分别执行，不得放入共享 120 秒宿主调用：

```powershell
RimDevTools.exe test run --mode quick --timeout-seconds 120
RimDevTools.exe data refresh --timeout-seconds 180
```

外层进程等待上限必须至少为：

```text
CLI --timeout-seconds + 60 秒清理余量
```

data refresh 的真实复测建议外层允许至少 300 秒，以覆盖游戏加载、导出、索引、游戏退出和配置恢复。

### 6.3 data refresh 诊断增强

无论首次独立复测是否成功，都应增强以下可诊断性：

- DataMod 在枚举、记录写入、索引构建、元数据写入、提交、原子替换、结果写入阶段输出明确日志。
- CLI 将最近观察到的导出阶段写入超时错误 details。
- 信号读取改用第 7 节的增量信号扫描器。
- 下一次导出继续清理同路径遗留 `.tmp`。
- 外部硬终止留下的事务由现有恢复机制处理，不将旧结果误认为本轮结果。

如果独立运行在 180 秒内成功，根因结论应写为“测试编排外层超时配置错误”，不为制造代码改动而改变数据库协议。

如果独立运行仍触发内部 `DATA_REFRESH_TIMEOUT`，再根据阶段日志定位并优化 RimSearcher DataMod；任何性能修改都需在嵌套仓库完成测试和版本验证。

### 6.4 报告修订

重新生成或修订 `RimDevTools_V2_系统输出测试报告.md`，必须记录：

- 完整命令。
- CLI 内部超时和外层等待上限。
- 进程退出码。
- 最终 JSON。
- 墙钟耗时。
- 是否存在残留 RimWorld/RimDevTools 进程。
- 配置事务、request/processing 文件和 `.tmp` 文件状态。

## 7. 改动三：大日志条件下完成信号可靠识别

### 7.1 当前缺陷

当前 test 和 data 监控逻辑把新增日志追加到字符串后，先裁剪到末尾 32768 字符，再搜索信号。如果一次读取的新增内容超过限制，且完成信号位于该块前部，信号会在检查前被删除。

### 7.2 实现方案

新增可复用的增量信号扫描组件，例如 `IncrementalLogSignalScanner`：

- 每次接收新读取的文本块。
- 在裁剪前搜索本轮所需的全部信号。
- 保留足够的尾部重叠文本，以识别跨两次读取拆分的信号。
- quick 匹配固定 `RUNTIME_READY_TO_CLOSE`。
- auto/xml 和 data 必须匹配当前 runId，旧 runId 不得放行。
- Player.log 截断或轮换导致 offset 回到 0 时，扫描状态同步重置。
- 不无限累计日志内容。

TestCommand 和 DataCommand 共用该组件，避免两套逻辑再次分叉。

### 7.3 回归用例

Fake RimWorld 新增大日志模式，至少生成：

- 超过 `logMaxLines` 默认阈值的日志行数。
- 总文本大于 32 KiB。
- 完成信号位于大块文本前部，后面继续写入足够多的普通日志。
- 一个完成信号被拆成两次写入的场景。

验收：

- quick 能收到 ready signal 并成功退出。
- auto/xml 能收到含当前 runId 的完成信号、验证结果 JSON 并成功退出。
- data 能识别当前 runId 的导出完成/失败信号。
- 内存缓冲不会随 Player.log 持续增长。

## 8. 改动四：Windows 隔离桌面静默运行

### 8.1 适用范围

默认进入隔离桌面：

- `test run --mode quick`
- `test run --mode auto`
- `test run --mode xml`
- `data refresh`

默认不进入：

- `test run --mode manual`
- `test settings`
- 不启动游戏的所有命令

### 8.2 Windows 实现

新增统一 `GameProcessLauncher`，普通桌面与隔离桌面都通过该入口启动 RimWorld。

隔离桌面实现使用 Windows API：

- `CreateDesktopW` 创建本轮唯一桌面。
- 桌面名包含安全前缀、进程 ID 和 runId，避免并发重名。
- `CreateProcessW` 的 `STARTUPINFO.lpDesktop` 指向新桌面。
- 将返回的 PID 包装为受监控 `Process`。
- 测试结束、超时、取消或失败时先终止本轮游戏，再关闭进程/线程句柄和桌面句柄。
- 不调用 `SwitchDesktop`，因此不会切走用户当前桌面。

隔离启动时无需依赖游戏 stdout 作为完成依据；Player.log 和结果文件仍是正式协议。普通桌面启动保持现有 stderr 诊断行为。

### 8.3 失败策略

配置或命令明确要求隔离桌面时，创建失败不得静默回退到可见桌面。返回稳定错误：

```text
ISOLATED_DESKTOP_CREATE_FAILED
ISOLATED_GAME_START_FAILED
ISOLATED_DESKTOP_CLEANUP_FAILED
```

错误 details 包含 Windows error code，但不把非稳定系统消息作为程序判断依据。

如果游戏无法终止，继续沿用现有安全规则：保留配置事务，不在游戏仍运行时恢复全局配置。

### 8.4 测试

- 参数互斥校验必须在任何环境写入前发生。
- 配置缺失时默认开启。
- `--no-isolated-desktop` 能覆盖配置 true。
- `--isolated-desktop` 能覆盖配置 false。
- manual 配置 true 时仍默认普通桌面。
- manual 显式开启时进入隔离桌面。
- Fake RimWorld 能报告其桌面名，测试确认不是调用进程桌面。
- 进程结束后桌面句柄可关闭，不残留同名桌面。
- 真实 auto 测试在隔离桌面仍能生成非空、尺寸正确的截图。
- data refresh 在隔离桌面仍能生成有效数据库并自动退出。

## 9. 改动五：quick/auto/xml 自动静音并恢复

### 9.1 范围

自动静音：

- quick
- auto
- xml

不自动静音：

- manual
- data refresh
- 其他不启动测试的命令

### 9.2 设置传递

CLI 在测试事务内向 LogSyncMod 设置文件写入临时字段，例如：

```xml
<testMuteAudio>True</testMuteAudio>
```

manual 写入 `False`。测试结束后，整个设置文件由 ConfigTransaction 精确恢复，因此不会永久留下该开关。

### 9.3 游戏内控制

在 LogSyncMod 主程序集实现统一音量控制器，以同时服务 quick 和 AutoTestProject：

1. LogSync 初始化完成后读取 `testMuteAudio`。
2. 第一次启用时保存当前 `UnityEngine.AudioListener.volume`。
3. 将 `AudioListener.volume` 设为 `0f`。
4. quick 在输出 `RUNTIME_READY_TO_CLOSE` 前恢复原值。
5. auto/xml 在输出本轮 `COMPLETED` 前恢复原值。
6. 游戏正常退出、自动测试异常收尾时执行幂等的 best-effort 恢复。
7. CLI 强制终止时，音量只存在于被终止进程内，不会影响玩家持久设置或 Windows 音量。

不得修改：

- Windows 音量混音器。
- RimWorld 持久主音量配置。
- 其他进程或其他游戏实例的音量。

### 9.4 测试

- 设置序列化和默认 false。
- quick 启动后记录原值、置零、完成前恢复。
- auto/xml 完成和失败收尾均调用幂等恢复。
- manual 不改变音量。
- 配置事务结束后设置 XML 与运行前逐字节一致。

## 10. 改动六：RimDevTools init

### 10.1 命令契约

```powershell
RimDevTools.exe init 1.6 --output D:\RimworldProject\NewMod
RimDevTools.exe init 1.7 --output D:\RimworldProject\NewMod
RimDevTools.exe init 1.8 --output D:\RimworldProject\NewMod
```

规则：

- `init` 是全局命令，不执行项目发现，不要求当前目录存在 `mod_config.jsonc`。
- 版本是唯一位置参数。
- `--output` 必填。
- 只接受 `1.6`、`1.7`、`1.8`，其他值返回 `VERSION_UNSUPPORTED`。
- 本轮不接受模组名、packageId 或作者参数。
- 输出目录不存在时创建；已存在时必须为空。
- 不提供 `--force`，已有任意文件时返回 `INIT_TARGET_NOT_EMPTY`。
- 使用同级暂存目录生成并验证完整骨架，成功后再安装到目标，失败不得留下半成品。

### 10.2 生成结构

以 1.6 为例：

```text
<output>/
├── .tools/
├── mod_config.jsonc
├── 1.6/
│   ├── Assemblies/
│   ├── Defs/
│   └── Patches/
├── 参考文档/
├── About/
│   ├── About.xml
│   └── Preview.png
├── Languages/
├── source/
│   └── TempProject/
│       └── 标准 TempProject 模板的全部内容
├── .gitignore
├── LoadFolders.xml
└── README.md
```

版本为 1.7 或 1.8 时，直接选择对应版本的组件模板。CLI 不负责在复制后硬编码改写 `LoadFolders.xml`、`mod_config.jsonc` 或 csproj；这些文件应当已经由对应版本模板提供正确内容。

### 10.3 模板来源

init 的职责是展开发布包 `components` 下的模板工程，不在 RimDevTools 程序集中嵌入项目文件，也不在 C# 代码中拼接 About.xml、JSONC、README、csproj、sln 或源码内容。

建议发布布局：

```text
<RimDevTools工具目录>/
├── RimDevTools.exe
├── rimsearcher.exe
├── Data/
├── Ilspy/
├── log/
├── modlist/
├── db/
└── components/
    └── ProjectTemplate/
        ├── manifest.json
        ├── 1.6/
        │   └── 完整的1.6项目模板树
        ├── 1.7/
        │   └── 完整的1.7项目模板树
        └── 1.8/
            └── 完整的1.8项目模板树
```

如果 RimDevTools.exe 继续发布在项目 `.tools` 内，则上述工具目录就是 `.tools`，实际路径为：

```text
.tools/components/ProjectTemplate/
```

每个版本目录保存应当释放到 `--output` 的项目工程内容，但不重复保存 `.tools`。`.tools` 由 RimDevTools.exe 所在共享工具目录复制一次，并明确排除 `components`。模板可以随版本独立演进，不要求三个版本的文件完全相同。

`manifest.json` 至少声明：

```json
{
  "schemaVersion": 1,
  "supportedVersions": ["1.6", "1.7", "1.8"],
  "requiredFiles": [],
  "requiredDirectories": []
}
```

其中：

- `supportedVersions` 决定可用版本，当前发布只允许 1.6、1.7、1.8。
- `requiredFiles` 用于复制完成后的完整性校验；文件缺失时 init 失败，不生成硬编码替代文件。
- `requiredDirectories` 用于声明必须存在但可能因“空目录不能被普通复制或版本控制保存”而缺失的目录。

init 固定流程：

1. 以 RimDevTools.exe 所在目录为基准定位 `components/ProjectTemplate/manifest.json`。
2. 校验 manifest schema 和请求版本。
3. 定位 `components/ProjectTemplate/<version>/`。
4. 拒绝版本模板内重复出现 `.tools`，将该版本模板树原样递归复制到同卷暂存目录。
5. 将 RimDevTools.exe 所在共享工具目录复制为暂存结果的 `.tools`，跳过顶层 `components`。
6. 复制完成后，才检查 manifest 声明的 `requiredDirectories`。
7. 仅当某个声明目录在复制结果中缺失时，才创建该目录。
8. 校验全部 `requiredFiles`、路径安全，以及模板和共享工具内不得包含 Reparse Point。
9. 验证成功后把暂存结果安装到 `--output`。

这意味着：

- 模板中已有的目录和文件一律以模板内容为准。
- CLI 不重写模板文件，不补写默认文本，不根据文件名猜测内容。
- CLI 只对 manifest 声明但模板中缺失的目录执行 `CreateDirectory`。
- 模板缺少必需文件时返回 `INIT_TEMPLATE_INVALID`，不能生成占位文件掩盖模板发布错误。
- `mod_config`、Preview、TempProject 源码以及其他项目内容来自对应版本组件模板；`.tools` 来自同一份共享发布工具目录。
- 空的数据库目录、日志目录、AutoTestOutput 等若需要创建，应写入 `requiredDirectories`，而不是硬编码在 InitCommand 中。
- 模板发布过程必须排除数据库、历史日志、截图、事务、缓存和构建产物；这属于模板组件的构建规则，不属于 init 运行时猜测规则。

发布脚本不得向三个版本模板分别注入 `.tools`。init 复制共享工具时必须排除 `components`，因此目标项目获得一份可运行工具组件，但不会把模板源再次嵌套复制进去。

### 10.4 结果输出

成功 JSON 至少包含：

```json
{
  "ok": true,
  "command": "init",
  "result": {
    "version": "1.6",
    "output": "D:\\RimworldProject\\NewMod",
    "createdEntries": []
  }
}
```

### 10.5 验证

对 1.6、1.7、1.8 分别初始化到临时目录，并验证：

- 目录树完整。
- 输出文件严格等于所选组件模板文件加一份共享工具文件；只有 manifest 声明且复制结果缺失的空目录允许作为额外项出现。
- 不同版本严格选择各自模板，不对复制后的文本文件执行版本替换。
- JSONC、XML、sln、csproj 均可解析。
- `RimDevTools.exe doctor` 能在新目录发现项目。
- `.tools/RimDevTools.exe --version` 能启动且组件版本匹配。
- 新项目不包含数据库、旧日志和 AutoTestOutput。
- 不支持的版本和非空目录在写入前失败。
- manifest 缺失、schema 不支持、版本模板缺失和 requiredFiles 缺失时均在安装目标前失败。
- 修改 components 中的模板文件后，无需修改或重新编译 InitCommand 业务逻辑即可影响下一次发布模板和 init 输出。

## 11. 改动七：指定目标模组与截图能力对齐
