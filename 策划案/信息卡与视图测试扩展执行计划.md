# 信息卡与视图测试扩展执行计划

## 1. 本次目标

本计划根据《修改计划.txt》及后续确认结果编写，目标是扩展游戏内 InfoCard UI 测试和视图截图测试，同时保持已有测试能力不重复、不回归。

本次纳入：

- 修复自动测试和 XML 测试的静音效果；
- 将现有三视图测试的用户概念扩展为“视图测试”；
- 增加植物生长阶段视图；
- 增加植物、动物、机械族、Pawn、Gene、Xenotype 的 InfoCard 测试；
- 新增独立的 Pawn 年龄阶段视图测试；动物年龄阶段则直接并入现有 AnimalThreeView；
- 增加建筑视图、地形 9×9 视图；
- 增加发型、头型、Gene、Xenotype 的 Pawn 三视图；
- 将 scope 收敛为 UI、Combat、View、Misc 四个正式范围；
- 复用现有相机高度、RootSize 和截图时序参数；
- 发型 presenter 选择必须考虑种族兼容性，包含 HAR（Humanoid Alien Races）种族。

本次明确不做：

- 不重新实现已经存在的建筑信息卡、地形信息卡、普通物品信息卡和现有 Pawn 三视图；
- 不做炮塔武器统一识别器。现有炮塔武器排除逻辑保持不扩展，本次只保证新增逻辑不绕过已有排除；
- 不把植物强行解释成 Pawn 式的左/正/右方向三视图；
- 不把 Gene/Xenotype 信息卡测试和 Pawn 外观视图测试混为同一个 CaseType。

## 2. 现状盘点与复用原则

现有代码已经具备以下能力：

- `BuildingInfoCard`、`TerrainInfoCard` 等 CaseType；
- `AutoTestInfoCardUiAdapter.Open(Def/Thing/Hediff)`；
- InfoCard 窗口打开、关闭、等待 Repaint、截图和语义证据记录；
- PawnKind、服装、武器 presenter 的生成式兼容判断；
- `AutoTestThreeViewAppearanceTemplate` 对 HairDef、HeadTypeDef、Gene/Xenotype、颜色和身体类型的复制；
- 视图测试的相机 Profile、三位置布局、暂停截图和清理流程。

新增用例应接入这些现有服务，不再复制一套窗口或截图生命周期。

核心原则：

1. `CaseType` 表示具体测试场景；
2. `Scope` 只表示 UI、Combat、View、Misc 四个大类；
3. 每个用例必须有唯一的 `CaseType + TargetIdentity`；
4. “发现目标”和“执行截图”分离；
5. presenter 不兼容时记录 `skipped` 和原因，不伪造成功。

## 3. Scope 重构

### 3.1 正式 scope

```text
UI       游戏内信息卡、配方窗口等 UI 测试
Combat   炮塔、远程、近战、战斗 Pawn 等战斗测试
View     Pawn 三视图、植物/建筑/地形视图、发型/头型/Gene/Xenotype 视图
Misc     技能口袋地图、非 UI/战斗/视图的诊断或结构性测试
```

`Standard` 保留为旧配置和 CLI 的兼容预设，不作为新的正式大类。它横跨 UI、Combat、View、Misc 四类常规测试，但继续保持现有排除规则，不隐式启用最耗时的 `CombatPawns` 和 `SkillPocketMaps`。四个 Scope 是用例分类，Standard 是选择预设，两者不在同一层级。

### 3.2 迁移范围

需要同步修改：

- `AutoTestScope` 枚举及旧值兼容映射；
- `LogSyncSettings` 的 scope 判断；
- `AutoTestRunner.ResolveScope` 和 `AutoTestRunner.SpecModule`；
- `AutoTestRuntimeApi.ListSuites`；
- RimDevTools 的 `--scope` 参数校验和帮助；
- 中文、繁中、英文语言键；
- XML Spec 的 scope 匹配。

XML 规则不应只依赖四个粗 scope 选择具体场景。后续应优先使用 `CaseType`/`testTypes` 匹配，例如只给 `GeneThreeView` 设置截图，而不影响 `GeneInfoCard`。

## 4. 静音修复

### 4.1 原因

当前 `TestAudioController` 直接修改 `AudioListener.volume`，而 RimWorld 的 `PrefsData.Apply()` 会再次把主音量写回 `AudioListener.volume`。因此日志可能显示已经静音，但游戏音频设置刷新后声音重新出现。

### 4.2 实施方案

1. `Arm` 时保存 `Prefs.VolumeMaster` 和当前 `AudioListener.volume`；
2. 使用 `Prefs.VolumeMaster = 0f` 进入静音状态；
3. 自动测试运行期间每帧或每若干 Tick 检查静音状态，被外部设置恢复时重新应用；
4. 自动测试、XML 测试、取消、超时、异常、启动失败都从统一 `finally` 路径恢复；
5. 恢复原始主音量，不永久修改玩家配置；
6. 增加日志字段：`Prefs.VolumeMaster`、`AudioListener.volume`、arm/restore 原因。

### 4.3 验收

- auto 模式全程无 UI、游戏、音乐和环境音；
- XML 模式全程无 UI、游戏、音乐和环境音；
- 测试结束后音量值与测试前一致；
- 测试中触发设置刷新后仍保持静音。

## 5. InfoCard 测试扩展

### 5.1 植物 InfoCard

对目标模组的植物 ThingDef：

1. 创建实际 `Plant` 实例；
2. 设置稳定的成长阶段和必要环境；
3. 通过现有 `Dialog_InfoCard(Thing)` 流程打开游戏内 InfoCard；
4. 截图、记录窗口语义状态；
5. 关闭并销毁植物。

植物 InfoCard 与植物视图是两个独立用例，不能因为植物视图成功而视为 InfoCard 成功。

### 5.2 动物、机械族、Pawn InfoCard

统一使用 Pawn InfoCard 执行器：

1. 从目标模组 PawnKindDef 生成实际 Pawn；
2. 默认使用该 PawnKind 可稳定生成的代表性阶段，不在 InfoCard 测试中展开全部年龄阶段；
3. 清理不需要的装备、服装和动态状态；
4. 选择 Pawn 并打开 Pawn 实例的 `Dialog_InfoCard`；
5. 验证 Stats、Character、Health 等可用标签页是否正常；
6. 截图并记录 PawnKind、Race、LifeStageDef、LifeStageIndex、Age、BodyType、Gender；
7. 清理 Pawn 和窗口。

动物、机械族和人形 Pawn 可以复用执行器，但报告中保留不同 CaseType，便于覆盖统计。

年龄阶段的完整截图只由 View scope 下的年龄阶段视图负责，InfoCard 测试不得因为年龄阶段数量而重复生成同一 PawnKind 的多份信息卡截图。

### 5.3 Gene/Xenotype InfoCard

- Gene：直接以 `GeneDef` 打开 InfoCard；
- Xenotype：直接以 `XenotypeDef` 打开 InfoCard；
- Gene/Xenotype InfoCard 不要求生成 Pawn；
- Biotech 不可用时记录明确的能力缺失状态。

## 6. 视图测试扩展

### 6.1 植物生长阶段视图

植物没有 Pawn 式的朝向三视图。RimWorld 原生 `PlantLifeStage` 正式分为三个阶段，因此本计划采用对应的“生长阶段三视图”：

- `Sowing`：播种阶段，使用接近 0 的 Growth，显示游戏通用播种 Graphic；
- `Growing`：生长阶段，Growth 应低于该植物的 `harvestMinGrowth`，优先展示 `immatureGraphicPath`；
- `Mature`：成熟阶段，Growth 设为 1，展示成熟 Graphic。

三个植物实例横向排列，复用现有三视图的固定相机参数和截图时序。每个实例都要刷新 Graphic，并在结果中记录 `PlantLifeStage`、具体 Growth、`harvestMinGrowth`、`visualSizeRange` 和 `maxMeshCount`。

对于没有 `immatureGraphicPath` 的植物，Growing 与 Mature 可能使用同一主贴图，但游戏仍会通过 `visualSizeRange` 和 `maxMeshCount` 随 Growth 改变尺寸与网格数量，因此仍保留三个阶段。树木等存在 leafless、polluted 或 snow overlay 的额外状态不计入基础生长阶段，本次不扩展为更多默认截图。

### 6.2 建筑视图

生成实际建筑实体并进行截图，重点验证：

- 建筑 Graphic；
- 多格尺寸；
- 朝向；
- 叠加组件或扩展 Graphic；
- 清理后地图状态。

建筑视图不替代建筑 InfoCard。

### 6.3 地形 9×9 视图

1. 分配独立的 9×9 区域；
2. 将区域所有格设置为目标 TerrainDef；
3. 对准区域中心截图；
4. 记录 9×9 应用数量和读回结果；
5. 恢复原 Terrain、Roof、Fog 和区域内可破坏 Thing。

如果当前地图清理成本过高，改用独立 pocket map，避免破坏玩家当前地图。

### 6.4 Pawn 年龄阶段三视图

新增独立 CaseType，例如 `PawnLifeStageThreeView`。该测试单独位于 View scope 下的新文件夹，不并入普通 `HumanoidThreeView` 或 `AlienThreeView`。

建议截图目录：

```text
View/PawnLifeStageThreeView/<RaceDefName>/
```

该测试以人种 RaceDef 为发现单位，而不是把同一种族的所有 PawnKindDef 都重复执行。每个人种选择一个能够稳定生成、能够覆盖其种族 Graphic 的代表 PawnKindDef。HAR 人种和其他 Humanlike 种族也纳入同一发现流程。

发现和执行规则：

1. 对目标模组涉及的 Humanlike RaceDef 去重；
2. 读取 `RaceDef.race.lifeStageAges`；
3. 使用同一索引读取代表 PawnKindDef 的 `PawnKindDef.lifeStages`；
4. 每个有效年龄阶段单独创建一个测试用例；
5. 每个年龄阶段只生成 1 张图片；该图片内同时排列 3 个同阶段、同外观模板的 Pawn，分别朝向西、南、北；
6. 生成阶段 Pawn 时优先通过 `PawnGenerationRequest` 指定阶段区间内的生物年龄；
7. 生成后验证 `pawn.ageTracker.CurLifeStageIndex` 与目标阶段一致；
8. 只有模组生成器拒绝指定年龄时，才使用 `LockCurrentLifeStageIndex` 回退；
9. 三个方向的 Pawn 必须复制同一外观模板、年龄和阶段，避免同一张图出现不同随机外观；
10. 所有 Pawn 必须裸体展示：清空 Apparel 和 Equipment，不穿服装、不持武器，便于观察身体、头部、比例和种族附加 Graphic；
11. 不主动移除种族固有基因、身体附加组件或 HAR body addon，避免破坏该人种真实外观。

年龄阶段测试只替换 Pawn 的生物年龄、LifeStage 和对应 Graphic 状态。摄影棚布局完全复用现有三视图逻辑：

- 相机高度、RootSize、截图等待时间和聚焦方式保持不变；
- 三个 Pawn 使用现有三视图的固定 AnchorCell 和相对格子位置；
- 西、南、北三个朝向及其对应格子不变；
- 不为 Baby、Child、Adult 或模组自定义阶段分别重新校准相机和站位；
- 即使阶段体型大小不同，也优先保持相同构图，便于直接比较不同年龄阶段的体型变化。

生命周期数量不能写死，应以运行时合并后的 Def 为准。原版人类当前常见 Baby、Child、PreTeenager、Teenager、Adult 共 5 个阶段；HAR 和其他种族模组可以声明任意数量及自定义 LifeStageDef。

人类阶段数可能多于 `DevelopmentalStage` 的粗分类。例如 Child、PreTeenager、Teenager 可能拥有不同 LifeStageDef、身体比例或渲染表现，因此不能只按 DevelopmentalStage 去重。

每张截图的背景标题必须明确显示阶段：

```text
第一行：人种/Pawn 的游戏内名称
第二行：RaceDefName 或代表 PawnKindDefName
第三行：阶段：<LifeStageDef.label> (<LifeStageDef.defName>)
第四行：年龄：<实际生物年龄> / StageIndex=<index>
```

阶段名称优先使用游戏当前语言下的 `LifeStageDef.label` 或 Adjective；缺少翻译或 label 时回退到 defName。

此测试允许同一人种的不同阶段拥有相同 Graphic。只要是不同 LifeStageDef，就各生成 1 张包含西、南、北三个朝向的图片；不因视觉签名相同而自动跳过，因为本测试目的就是完整展示该人种声明的年龄阶段。

### 6.5 动物年龄阶段三视图

动物年龄阶段不新增独立顶层 CaseType，直接扩展现有 `AnimalThreeView`。

对每个 Animal PawnKindDef：

1. 读取 `race.lifeStageAges`；
2. 每个不同 LifeStageDef 分别执行一次三视图；
3. 每个阶段只输出 1 张图片，图片内同时显示 3 个同阶段动物，分别朝向西、南、北；
4. 三个方向使用相同年龄、性别、颜色和随机 Graphic 变体；
5. 阶段年龄取当前阶段区间内的稳定值，并验证实际 LifeStageIndex；
6. 标题写明动物名称、PawnKindDef、阶段名称、LifeStageDef 和实际年龄。

动物年龄阶段同样只替换年龄和 LifeStage，继续沿用现有 AnimalThreeView 的相机 Profile、AnchorCell、三个单位格子、相对间距和西/南/北朝向，不针对幼体、亚成年和成年重新调整相机或摆放位置。

普通动物通常为 Baby、Juvenile、Adult 三个阶段，但模组动物可以声明任意数量。动物阶段同样以实际 LifeStageDef 为准，不仅依赖 DevelopmentalStage。

动物截图标题建议：

```text
第一行：动物游戏内名称
第二行：PawnKindDefName / RaceDefName
第三行：阶段：<LifeStageDef.label> (<LifeStageDef.defName>)
第四行：年龄：<实际生物年龄> / StageIndex=<index>
```

### 6.6 发型/头型三视图

发型和头型必须配合实际可用的小人，不能简单使用固定人类 Pawn。

Presenter 选择沿用武器持有判断的思路：

1. 枚举目标模组提供的候选 PawnKindDef；
2. 生成探测 Pawn；
3. 设置性别、BodyType、Race；
4. 应用 HairDef 或 HeadTypeDef；
5. 验证应用后的 Pawn Graphic 可正常生成；
6. 只有通过验证的 Pawn 才作为三视图 presenter。

原版兼容判断至少考虑：

- `StyleItemDef.styleTags`；
- `styleGender`；
- `requiredGene`；
- `requiredMutant`；
- `noGraphic`；
- `HeadTypeDef` 与 Race/BodyType 是否匹配。

HAR 兼容判断：

- 不直接引用 AlienRace.dll，使用可选反射，避免把 HAR 变成编译期硬依赖；
- 若 Pawn Race 是 `AlienRace.ThingDef_AlienRace`，读取其 `alienRace.styleSettings`；
- 优先调用 HAR `StyleSettings.IsValidStyle(styleDef, pawn)` 判断发型是否允许；
- 参考 HAR `alienPartGenerator.headTypes`、`bodyTypes`、graphic paths 和 body addons；
- 生成后调用现有 Graphic 刷新逻辑，必要时触发 HAR AlienComp 的扩展 Graphic 重建；
- 如果 HAR 不可用，则退回原版判断，不因缺少 HAR 直接失败。

每个发型/头型用例结果中记录最终 presenter Race、PawnKind、Gender、BodyType 和兼容判断来源。

### 6.7 Gene/Xenotype 外观三视图

基因视图的目标是“让小人实际持有该基因后截图”，不是只截 GeneDef 信息卡。

#### GeneThreeView

1. 生成一个兼容的基线 Pawn；
2. 清理其原有 Xenogene；
3. 应用目标 GeneDef；
4. 刷新基因、颜色和 PawnRenderTree；
5. 生成三份 Pawn 进行三视图；
6. 记录 Gene 是否实际存在于 Endogenes/Xenogenes。

#### XenotypeThreeView

1. 生成兼容的基线 Pawn；
2. 应用目标 Xenotype；
3. 确认其 GeneSet 与 Xenotype 一致；
4. 刷新 Graphic 和扩展渲染节点；
5. 生成三份 Pawn 进行三视图。

#### 外观无变化的 Gene 过滤

采用“静态预筛选 + 动态验证”两层机制。

静态预筛选检查：

- `HasDefinedGraphicProperties`/`renderNodeProperties`；
- `hairColorOverride`；
- `skinColorBase`、`skinColorOverride`；
- `bodyType`；
- `forcedHeadTypes`；
- `forcedHair`；
- `hairTagFilter`、`beardTagFilter`；
- Gene 的 DefModExtension；
- HAR 的 `AlienRace.Utilities.BodyAddonGene` 等可选扩展。

动态验证检查：

1. 记录应用 Gene 前的外观签名；
2. 应用 Gene/Xenotype；
3. 刷新 Renderer；
4. 记录应用后的外观签名；
5. 如果签名无变化，再尝试兼容的其他 Race/Gender/BodyType presenter；
6. 所有兼容 presenter 都无变化时，才将 GeneThreeView 标记为 `skipped: no_visual_effect`。

不能只依赖静态字段排除，因为 HAR 可能通过扩展 Graphic、条件节点、body addon 或自定义 Comp 改变外观。

对于仅影响行为、能力或数值而不影响外观的 Gene：

- Gene InfoCard 仍然执行；
- GeneThreeView 记录跳过原因；
- 不把“没有外观变化”判定为 Gene 本身失败。

## 7. 图片目录与文件命名

### 7.1 全局命名规则

当前图片名称主要由结果序号、DefName 和 StageSuffix 组成。本次要求由 `AutoTestScreenshotService` 统一修改所有产出图片的文件名，在当前名称基础上追加目标对象的游戏内名称。

统一格式：

```text
<序号>_<DefName>(<游戏内名称>)_<StageSuffix>.png
```

没有 StageSuffix 时：

```text
<序号>_<DefName>(<游戏内名称>).png
```

示例：

```text
0042_MyMod_Wolf(月狼)_triptych.png
0043_MyMod_Race@HumanlikeChild(月族)_triptych.png
0044_MyMod_Terrain(黑曜石地板).png
```

“游戏内名称”取截图时当前语言下的 `result.Label`/`LabelCap`。如果 Label 为空则回退到 DefName，但仍保留括号格式。

该规则必须集中在截图服务中实现，对以下所有图片统一生效：

- InfoCard；
- View；
- Combat；
- 失败截图；
- 分阶段截图和动作截图。

DefName、游戏内名称和 StageSuffix 分别进行文件名非法字符清理。为避免 Windows 路径过长，游戏内名称允许截断，但 DefName 和唯一 StageSuffix 不得被截掉，确保文件仍可唯一定位测试对象。

### 7.2 Pawn 年龄阶段目录

Pawn 年龄阶段使用独立目录：

```text
Screenshots/View/PawnLifeStageThreeView/<RaceDefName>/
```

每个阶段一张三视图，例如：

```text
0001_MyRace@HumanlikeBaby(月族)_HumanlikeBaby_triptych.png
0002_MyRace@HumanlikeChild(月族)_HumanlikeChild_triptych.png
0003_MyRace@HumanlikeAdult(月族)_HumanlikeAdult_triptych.png
```

动物仍保存在 `View/AnimalThreeView` 下，可按 PawnKindDef 或 RaceDef 设置相对子目录，避免多个阶段图片混杂。

## 8. 数据模型和执行器

新增用例建议采用统一描述：

```text
AutoTestCaseDescriptor
    CaseType
    Scope
    TargetDef
    PresenterResolver
    Executor
    ScreenshotProfile
    RequiredExpansion
    SkipReason
```

推荐执行器：

- `InfoCardDefExecutor`；
- `InfoCardThingExecutor`；
- `InfoCardPawnExecutor`；
- `PlantGrowthViewExecutor`；
- `BuildingViewExecutor`；
- `TerrainPatchViewExecutor`；
- `PawnTriptychAppearanceExecutor`。

现有普通 InfoCard 和三视图流程继续复用，不进行大规模重写；新增执行器只负责新 CaseType 的发现、准备和清理。

## 10. 验收标准

- 既有建筑/地形/物品信息卡不产生重复用例；
- 植物 InfoCard 截图的是游戏内实际 InfoCard；
- 动物、机械族和 Pawn InfoCard 使用实际 Pawn；
- Pawn 年龄阶段测试位于独立的 `View/PawnLifeStageThreeView/<RaceDefName>` 文件夹；
- 普通 Humanoid/Alien 三视图不会因为年龄阶段重复截图；
- 每个人种的每个 LifeStageDef 只产出 1 张裸体 Pawn 图片，图内同时包含西、南、北三个朝向；
- 动物阶段数量从运行时 `lifeStageAges` 动态识别，并直接纳入 AnimalThreeView；
- 人类当前常见 5 阶段、普通动物常见 3 阶段，但模组自定义数量能够正常发现；
- Pawn 和动物阶段截图背景标题包含游戏内阶段名称、LifeStageDef、年龄和 StageIndex；
- Pawn 年龄阶段截图中不包含服装和武器，但保留种族固有基因与 HAR body addon；
- Pawn 和动物年龄阶段截图沿用现有三视图的相机参数、AnchorCell、三个单位格子、相对间距和朝向布局；
- 年龄阶段测试不得引入按阶段单独校准的相机参数或站位配置；
- 植物视图显示三个明确成长阶段；
- 地形视图准确显示 9×9 区域；
- 发型/头型只使用兼容的 Pawn presenter；
- HAR 种族可参与发型/头型视图，HAR 未启用时不影响原版测试；
- Gene/Xenotype 视图中的 Pawn 实际持有目标基因/种族；
- 无外观变化的 Gene 只跳过视图，不跳过 InfoCard；
- 自动测试和 XML 测试全程静音，结束后恢复原音量；
- 所有新增用例均有唯一 CaseId、明确 Scope、截图结果和清理结果；
- 所有截图文件名均在原 DefName 基础上追加括号包裹的游戏内名称；
- 视图截图继续沿用现有相机高度、RootSize 和截图时序参数。
