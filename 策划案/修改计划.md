# RimDevTools 命令直观化修改执行计划

## 1. 本次确定的目标

本次修改只处理以下内容：

1. 将参考模组命令组从 `ref` 统一改为 `mod`，消除 `ref` 可能被理解为 reference、Def 或其他查询对象的歧义。
2. 简化参考模组命令和测试参数命名。
3. 不保留旧命令、旧参数或旧别名；代码、帮助、README、skill、测试和发布包文档统一使用新名称。
4. 优化帮助文本，让用户和 AI 可以直接从顶层帮助看出完整命令层级。
5. 增加测试事务状态查看入口：`test cleanup --status`。
6. 为参考模组复制增加安全预览：`mod copy --dry-run`。
7. 为 `doctor` 增加模组 About 目录和预览图检查。
8. 在 skill 文档中清楚说明 `test settings` 的实际用途、修改内容和适用场景。

## 2. 明确不实施的内容

以下内容本次不做，也不要在实现过程中顺带加入：

- 不增加 `--output json|text` 或 `--json`，保持现有 JSON 输出约定。
- 不增加 `languages` 命令及翻译检查功能。
- 不保留 `ref`、`ref search`、`ref pull`、`ref deps`、`ref related` 等旧命令支持。
- 不保留 `--auto-test-scope`、`--auto-test-defname` 和 `scope=all`。
- 不增加 `mod copy --plan`，只保留 `--dry-run`。
- 不增加 `test status`，只实现 `test cleanup --status`。
- 不执行其他未列入本计划的命令、配置、输出格式或功能设计。

## 3. 最终命令设计

### 3.1 参考模组命令组

统一将 `ref` 改为 `mod`：

```text
mod search <keyword> [--fuzzy]
mod copy <query> [--version <value>] [--deps] [--include-ignored] [--fuzzy] [--overwrite-existing] [--dry-run]
mod dependencies <query> [--version <value>] [--fuzzy]
mod dependents <query> [--version <value>] [--fuzzy]
```

参数替换关系：

| 原名称 | 最终名称 |
|---|---|
| `ref search` | `mod search` |
| `ref pull` | `mod copy` |
| `ref deps` | `mod dependencies` |
| `ref related` | `mod dependents` |
| `--all` | `--include-ignored` |
| `--force` | `--overwrite-existing` |

命令行为保持原有功能：

- `mod search` 仍搜索 RimWorld `Mods` 目录和配置的 Workshop 目录。
- `mod copy` 仍复制模组并反编译程序集。
- `--deps` 仍表示拉取完整硬依赖闭包。
- `--include-ignored` 表示不应用 `pull_ignore_folders`。
- `--overwrite-existing` 表示允许替换已存在的目标。
- `--dry-run` 只输出解析结果和执行计划，不复制、不反编译、不覆盖。
- 歧义、依赖循环、目标碰撞和路径安全检查仍必须在实际写入前完成。

### 3.2 测试命令参数

保留：

```text
test run --active-mods-file <path>
```

删除：

```text
--mods-file
--auto-test-scope
--auto-test-defname
```

`--scope` 和 `--defname` 的最终规则：

- `--scope` 只允许用于 `--mode auto` 或 `--mode xml`，可重复指定。
- `--defname` 只允许用于 `--mode auto`，可重复指定。
- `scope=all` 返回无效参数错误，不再映射到 `Standard`。
- 新命令帮助必须列出允许的 scope 值和可复制的修正示例。
- 不适用模式的选项必须在参数校验阶段直接返回 `INVALID_ARGUMENT`，不能接受后静默忽略。

隔离桌面规则保持现有设计：

- `--isolated-desktop` 与 `--no-isolated-desktop` 同时出现时直接报错。
- 所有互斥布尔选项使用一致的冲突校验方式。

### 3.3 测试事务状态

保留现有清理命令，并增加只读状态模式：

```text
test cleanup --status
test cleanup --status --dry-run
```

`--status` 不取得写入锁、不修改文件，只报告：

- 是否存在遗留配置事务；
- 事务目录和 runId；
- 是否存在部署暂存/备份产物；
- 当前 RimWorld 是否运行；
- 如果需要清理，输出建议执行的命令。

普通 `test cleanup` 的恢复行为保持不变；`--dry-run` 仍表示只预览、不修改。

### 3.4 `test settings` 文档说明

`test settings` 暂时保留，不改变其代码行为，但必须在 skill 参考文档中说明：

- 它是“持久化 LogSync 设置”命令，不是测试命令；
- 它会把日志路径设置到当前项目的 `.tools/log/精选日志.log`；
- 它会写入 `mod_config.jsonc` 中的 `log_keywords`；
- 它会更新 LogSync 的自动测试相关开关和路径；
- 它会永久写入设置，不像 `test run` 那样在测试结束后恢复；
- 适用场景是手动启动 RimWorld 前准备 LogSync；正常自动测试优先使用 `test run`；
- 执行前会等待已有 RimWorld 退出并取得共享环境锁。

重点优化文件：

```text
artifacts/RimDevTools-Package/.agents/skills/rimdevtools/references/commands-and-config.md
```

模板源文件也必须同步更新，避免下次重新发布时覆盖说明：

```text
components/ProjectTemplate/1.6/.claude/skills/rimdevtools/references/commands-and-config.md
```

## 4. 帮助和文档调整

### 4.1 顶层帮助

顶层帮助直接列出完整二级命令：

```text
doctor
deploy
mod search
mod copy
mod dependencies
mod dependents
test run
test settings
test cleanup
mods install-tools
```

不要求用户先执行 `mod --help` 或 `test --help` 才能知道子命令名称。

### 4.2 分组帮助

- `mod --help` 的 Usage 和 Subcommands 全部使用 `mod` 命名。
- `test --help` 的 Usage 必须包含 `cleanup`，不能继续显示 `test <run|settings>`。
- `doctor --help` 的 Usage 必须显示 `doctor [--verbose]`，并明确 `--verbose` 的作用。
- `mods install-tools` 继续保留现有命令名，帮助内容不扩展到其他工具安装功能。

### 4.3 版本入口说明

`--version` 继续只接受唯一参数：

```text
RimDevTools.exe --version
```

帮助文本不得把它描述为可附加到任意命令后的通用选项；需要在文档中说明 `doctor --version` 等形式不属于支持用法。

## 5. `doctor` 新增检查

新增两个非阻塞检查项：

1. `About/About.xml`
   - 文件存在：检查通过；
   - 文件不存在：warning，不阻止 `doctor` 完成。
2. `About/Preview.png`
   - 文件存在且小于 `1 MiB`（1,048,576 字节）：检查通过；
   - 文件不存在：warning；
   - 文件大小大于或等于 `1 MiB`：warning；
   - 任意异常只记录 warning，不阻止后续命令。

检查结果应纳入现有 `doctor` 的 `warningCount` 和检查列表；`--verbose` 显示完整检查项，默认模式显示需要处理的 warning。

### 阶段一：命令路由和参数契约

1. 修改命令路径解析和 dispatch：`ref ...` 全部替换为 `mod ...`。
2. 更新参数契约：`--include-ignored`、`--overwrite-existing`、`--active-mods-file`、`--dry-run`、`--status`。
3. 删除旧参数和旧命令支持，不实现兼容别名。
4. 删除 `scope=all` 的特殊映射，改为无效参数。
5. 增加不适用模式和互斥参数的提前校验。

### 阶段二：参考模组复制预览

1. 将原 `ref pull` 的实现改名并迁移为 `mod copy`。
2. 增加 `--dry-run` 分支。

5. `--overwrite-existing` 只在非 dry-run 且预检通过后允许替换。

## 7. 验收标准

### 命令和参数

- `mod search/copy/dependencies/dependents` 全部可用。
- `ref ...` 全部返回未知命令，不保留兼容入口。
- `--include-ignored`、`--overwrite-existing`、`--active-mods-file` 可用。
- `--all`、`--force`、`--mods-file`、`--auto-test-scope`、`--auto-test-defname` 和 `scope=all` 不再被接受。
- `mod copy --dry-run` 不修改文件，也不执行反编译。

### 测试事务

- `test cleanup --status` 只读显示事务和部署现场状态。
- 普通 `test cleanup` 的原有恢复能力不受影响。
- `test settings` 的文档能清楚说明它何时有用、会修改什么以及不会自动恢复。

### 帮助和文档

- 顶层帮助直接列出所有二级命令。
- `test --help` 包含 cleanup。
- `doctor --help` 包含 `--verbose`。
- skill、README、About.xml 和发布包参考文档不再出现旧命令用法。

### doctor

- About.xml 和 Preview.png 缺失或 Preview.png 超过 1 MiB 时只产生 warning。
- warning 会出现在默认摘要和 verbose 检查列表中。

- `languages` 翻译检查；
- 任何未在本计划列出的新命令、别名、配置字段或自动修复行为。
